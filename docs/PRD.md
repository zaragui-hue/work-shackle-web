# Work Shackle V1 产品需求文档（PRD）

> 文档状态：V1 范围冻结版（已补充可安装交付、国潮治愈卡通视觉规范、原创表情/Meme 规范）  
> 产品形态：macOS / Windows 本地桌面应用  
> 产品名称：Work Shackle  
> V1 核心原则：本地、轻量、无需登录、无 AI、数据即时持久化、年轻化打工人体验

---

# 1. 产品概述

## 1.1 产品定位

Work Shackle 是一个面向个人使用的本地桌面工作台，用于管理每日任务、DDL、当前工作状态、下班倒计时、加班记录和历史任务。

产品希望解决两个核心问题：

1. 用户每天能够快速知道“今天要干什么、什么最急、什么时候下班”；
2. 用户的任务、完成记录、延期原因、对接人、工作状态等信息能够长期保存在本地，为未来周报、月报、季度总结和年终总结提供基础数据。

产品不是企业项目管理工具，也不是考勤软件，不提供老板视角、KPI、绩效、团队协作等能力。

## 1.2 产品设计原则

> **认真管理任务，轻松面对上班。**

核心原则：

- 任务信息必须准确、清晰；
- 数据必须稳定保存在本地；
- 不要求登录；
- V1 不依赖云端服务；
- 搞笑文案、表情和微动效用于增强体验，但不能影响核心操作；
- 不将“摸鱼”“休息”等状态转化为效率评分；
- V1 优先考虑低复杂度、低维护成本和 Cursor Vibe Coding 的可实现性。

# 4. 产品交付形态

Work Shackle V1 为可安装的本地桌面应用，不以网页或仅源码运行方式作为最终交付形态。

V1 需要支持：

- macOS 可点击安装并启动；
- Windows 可点击安装并启动；
- 安装后可像普通桌面软件一样从系统应用入口启动；
- 安装包内包含 V1 所需本地 UI、表情、动效等资源；
- 核心功能不依赖远程服务器才能运行。

具体安装包格式、签名、公证、自动更新策略在技术架构阶段确定。

# 5. 本地数据与工作目录

## 5.1 数据原则

所有业务数据均保存在用户电脑本地。

核心结构化数据使用本地 SQLite 数据库持久化，包括但不限于：

- 任务；
- 任务备注；
- 计划时间；
- DDL；
- 紧急程度；
- 任务状态；
- 对接人；
- 提醒节点；
- 延期历史；
- 完成时间；
- 工作状态记录；
- 上下班设置；
- 加班记录；
- 忙碌状态配置；
- 用户自定义文案；
- 其他业务设置。

所有有效操作完成后立即持久化，不依赖 App 退出时统一保存。

因此在以下场景下，已保存数据仍应存在：

- 关闭 App；
- 重启电脑；
- 电脑休眠后恢复；
- App 意外退出；
- 数天后重新打开 App。

V1 不提供本地自动备份和云端备份。

## 5.2 用户自定义工作目录优先

如果用户已经手动设置过且该目录仍通过安全校验：

> 永远优先使用用户设置的目录。

例如：

```text
macOS:
/Users/username/Documents/MyJob

Windows:
E:\工作记录
```

此时不额外创建 `Work Shackle` 子文件夹。

数据库、时间目录和业务文件直接使用该工作目录。

工作目录必须位于可靠的本机文件系统。V1 不支持网络文件系统作为工作目录：

- Windows UNC / 网络路径必须拒绝；
- macOS 网络挂载和移动挂载目录不作为支持的数据目录；
- 对明确识别出的云同步目录，提示用户重新选择本地目录；
- 默认目录和用户自定义目录都必须经过 Rust 最终校验，不能只依赖前端判断。

未通过安全校验的目录不得创建或打开 Work Shackle 数据库，也不得保存为有效工作目录。

## 5.3 用户未设置工作目录

仅当用户从未设置过工作目录时，App 自动创建默认目录。

### macOS

```text
~/Documents/Work Shackle
```

### Windows

优先：

```text
D:\Work Shackle
```

如果 D 盘不存在或不可写，则使用：

```text
%USERPROFILE%\Documents\Work Shackle
```

## 5.4 工作目录内部结构

建议：

```text
工作目录/
│
├── .data/
│   └── work-shackle.db
│
├── 2026/
│   ├── 08/
│   │   ├── 第32周_08.03-08.09/
│   │   └── 第33周_08.10-08.16/
│   └── ...
│
└── ...
```

`.data/work-shackle.db` 存储 V1 的核心结构化数据。

年/月/周目录用于按时间沉淀用户数据，并为未来周报、月报、年终总结及其他导出能力预留统一目录结构。

## 5.5 年/月/周目录规则

目录层级：

```text
年
└── 月
    └── 周
```

周目录以周一至周日作为一个完整周期。

跨月周按“周一所在月份”归档。

例如：

```text
2026-08-31 ～ 2026-09-06
```

归入：

```text
2026/
└── 08/
    └── 第36周_08.31-09.06/
```

## 5.6 工作目录被移动或删除

如果用户曾经设置的工作目录在启动时不存在：

App 不得自动切换到默认目录。

提示：

> 之前设置的工作目录找不到了，可能被移动或删除。

用户可选择：

- 选择新的工作目录；
- 使用默认目录。

只有用户主动选择“使用默认目录”时，才创建默认 `Work Shackle` 目录。

## 5.7 用户主动清理本地数据

用户允许通过 Finder / Windows 文件资源管理器直接删除工作目录中的数据。

V1 不提供数据恢复能力。

如果目录被删除后再次打开 App，按“工作目录不存在”流程处理。

如果 App 正在运行时目录被删除，在下一次写入时必须明确提示保存失败，不得向用户显示“保存成功”。

# 6. 工作时间与下班倒计时

## 6.1 默认上下班时间

用户可以设置默认工作时间，例如：

```text
上班：09:30
下班：18:30
```

## 6.2 今日临时工作时间

用户可以仅修改今天的上下班时间。

例如：

```text
今天：
10:00 上班
20:00 下班
```

当日临时设置只影响当天，第二天自动恢复默认设置。

## 6.3 上班前状态

V1 不显示“距离上班还有多久”。

用户在上班时间前打开 App，不进入专门的上班前倒计时模式。

## 6.4 工作中倒计时

正常工作期间首页显示：

```text
距离下班还有

06 : 42 : 17
```

并随机显示轻松文案，例如：

- 工资正在缓慢到账。
- 今天也是靠下班时间支撑的一天。
- 已经开始期待电脑合上的声音。

# 7. 工作状态

## 7.1 固定状态

V1 工作状态名称、图标和顺序固定。

用户仅允许修改各状态对应的文案，不允许：

- 新增状态；
- 删除状态；
- 修改状态名称；
- 修改状态图标；
- 调整状态顺序。

默认状态：

- 🧱 工作中
- 🎧 专注搬砖
- 💻 会议中
- 🚨 临时插单
- 🏃 被需求追杀
- 🐟 摸鱼中
- 👂 八卦一下
- ☕ 喝点东西
- 🍚 午餐中
- 💤 午休续命
- 🫠 发会儿呆
- 👜 准备下班
- 🌙 加班中

其中“加班中”为系统联动状态，不作为普通自由状态使用。

## 7.2 状态文案

每个状态允许用户配置多条文案。

进入该状态时随机显示其中一条。

示例：

```text
🐟 摸鱼中

工作暂停一下，人生加载一会儿。
```

下次可能显示：

```text
🐟 摸鱼中

正在进行一些与 KPI 关系不大的重要活动。
```

## 7.3 状态时间段与提醒

每个普通状态允许配置建议持续时间和提醒。

提醒只作为建议，不强制切换状态。

## 7.4 午餐状态

提供：

> 🍚 午餐中

用户可以设置默认午餐时间，例如：

```text
12:00 - 13:00
```

到达午餐时间后可轻量提醒：

> 到饭点了。工作可以等等，饭凉了是真的不好吃。

系统不强制切换当前状态。

## 7.5 状态时间线

用户切换状态后，App 记录当天轻量状态时间线。

状态时间线仅用于个人回顾，不产生：

- 工作效率评分；
- 摸鱼评分；
- KPI；
- 绩效数据。

# 8. 下班与加班

## 8.1 到达下班时间

到达用户当天的下班时间后：

> 不自动进入加班。

页面展示：

```text
理论下班时间到

今天的正常打工时间结束了。

[正常下班]
[开启加班模式]
```

## 8.2 正常下班

用户选择“正常下班”后：

- 当天正常工作结束；
- 不计算加班；
- 首页进入下班完成状态；
- 可随机显示结束文案。

示例：

- 今天就到这儿，剩下的交给明天的自己。
- 已下班。工作消息从现在开始酌情理解。
- 电脑合上，恩怨清零。

## 8.3 开启加班模式

只有用户主动点击“开启加班模式”才开始记录加班。

系统自动进入：

> 🌙 加班中

显示：

```text
🌙 加班模式

已加班
01 : 27 : 36

[结束加班]
```

规则：

> 超过下班时间，不代表自动加班。

## 8.4 手动结束加班

用户点击“结束加班”后记录：

- 加班开始时间；
- 加班结束时间；
- 加班总时长；
- 结束方式：手动。

## 8.5 05:00 自动结束

如果用户开启加班后没有手动结束：

> 该工作日的当地时间 05:00 截止线自动结束。

记录：

- 实际开始时间；
- 自动结束时间 = 该工作日截止线 05:00；
- 结束方式 = 系统自动。

## 8.6 App 中途退出

开启加班后，即使：

- 关闭 App；
- 电脑休眠；
- 电脑关机；

加班状态仍保存。

下一次启动 App 时，如果当前时间已经超过自动结束时间，则补记：

```text
结束时间：该工作日截止线 05:00
结束方式：系统自动结束
```

不能把重新打开 App 的时间作为结束时间。

## 8.7 加班归属日期

加班与工作状态按当地时间 05:00 作为工作日截止线：

```text
local time < 05:00  → work_date 归前一天
local time >= 05:00 → work_date 归当天
```

因此跨零点但未跨过 05:00 的加班仍归属于上一工作日。

例如：

```text
8月12日 18:30 开始
8月13日 01:30 结束
```

全部算作 8 月 12 日工作日的加班。

05:00 是上一工作日加班的最终截断点。

任务 planned date 和 DDL 的日历日期按普通本地日历日期计算，不使用这套 05:00 工作日归属规则。

# 9. 今日任务

## 9.1 今日任务来源

“今日任务”由以下内容组成：

1. 计划时间在今天的任务；
2. DDL 在今天且尚未完成的任务；
3. 用户主动安排到今天的任务；
4. 历史已经逾期、但仍未完成的任务。

逾期任务应单独给予“历史欠账/已逾期”视觉提示，不混淆为当天正式安排。

## 9.2 今日已完成区域

今日页面展示：

```text
✓ 今天已经搞定 5 件事
```

支持展开查看已完成任务。

已完成任务：

- 自动记录完成时间；
- 不删除；
- 支持撤销完成；
- 保留在历史任务中。

# 10. 新建任务

## 10.1 字段

| 字段 | 规则 |
|---|---|
| 任务名称 | 必填 |
| 备注 | 可选，多行 |
| 计划时间 | 默认当前日期 + 当前时分 |
| DDL | 可选，精确到分钟 |
| 紧急程度 | 默认“正常” |
| 对接人 | 可选 |
| 自定义提醒 | 最多 3 个 |
| 主状态 | 默认“未开始” |
| 创建时间 | 自动记录 |
| 完成时间 | 完成时自动记录 |
| 延期历史 | 自动记录 |
| 任务数量 | 不设人为上限 |

## 10.2 计划时间

创建任务时：

> 默认值为当前日期 + 当前时间，精确到分钟。

用户可修改。

计划时间用于：

- 判断任务属于哪一天；
- DDL 时间进度计算；
- 日历任务统计。

## 10.3 DDL

DDL 可选。

如果填写，则精确到：

> 年/月/日/时/分。

设置 DDL 后启用：

- 时间进度条；
- DDL 系统提醒；
- DDL 到点提醒；
- 逾期状态判断。

# 11. 任务紧急程度

V1 固定五档，不允许用户修改档位结构。

| 等级 | 展示 | 副文案 |
|---|---|---|
| 1 | 🫧 不急 | 反正老板也不催 |
| 2 | 🙂 正常 | 该干还是得干 |
| 3 | 😵 有点急 | 再拖就要被问了 |
| 4 | 🔥 很急 | 已经有人开始等了 |
| 5 | 🚨 现在立刻马上要 | 别排了，先干这个 |

默认：

> 🙂 正常

“现在立刻马上要”是最高紧急程度，不是任务生命周期状态。

# 12. 任务主状态

任务主状态为：

- 未开始；
- 进行中；
- 暂停；
- 等别人；
- 已完成；
- 已取消。

“延期”不作为互斥主状态。

例如一个任务可以同时：

```text
主状态：进行中
延期次数：2 次
```

延期作为任务历史属性保存。

# 13. 对接人

## 13.1 添加

用户可手动输入对接人。

首次使用的新名称保存到本地对接人列表。

后续创建任务时可以直接选择。

## 13.2 对接人列表

示例：

```text
最近使用

Anthony
小王
研发
测试

+ 添加新对接人
```

## 13.3 从列表移除

用户可以将某个对接人从可选列表中移除。

重要规则：

> 从选择列表移除 ≠ 删除历史任务中的对接人信息。

历史任务中已经保存的对接人名称永久保留。

---

# 14. 用户自定义提醒

每个任务最多设置：

> 3 个用户自定义提醒节点。

例如：

```text
14:00
先找研发确认

16:30
检查 PRD

17:30
准备提交
```

超过 3 个时禁止继续添加。

可使用轻松提示：

> 最多 3 个提醒，先别把自己催疯。

用户自定义提醒与系统 DDL 提醒相互独立。

---

# 15. DDL 系统提醒

## 15.1 DDL 前提醒

固定提醒 3 次：

1. DDL 前 60 分钟；
2. DDL 前 30 分钟；
3. DDL 前 10 分钟。

这 3 次不占任务的 3 个用户自定义提醒名额。

如果任务在提醒发生前已经完成，则后续该任务的 DDL 提醒全部取消。

## 15.2 DDL 到点事件

如果任务在 DDL 到达时仍未完成：

触发“DDL 已到”事件。

该事件不计入前述 3 次提前提醒。

表现：

- 操作系统本地通知；
- 应用图标请求用户注意；
- App 打开时出现前置提醒窗口；
- 任务进入逾期判断。

## 15.3 应用图标提醒

macOS：

- Dock 图标请求用户注意 / 跳动。

Windows：

- 任务栏图标闪烁 / 请求用户注意。

产品统一定义为：

> 明显但不过度的应用图标提醒。

## 15.4 App 内前置提醒

如果 App 当前处于打开状态：

DDL 关键提醒采用最前置轻量窗口展示。

要求：

- 不使用传统错误警告框；
- 使用软萌小角色；
- 结合轻量动态表情；
- 文案随机；
- 提供“打开任务”等明确操作。

## 15.5 App 完全退出时

V1 不要求额外开发常驻后台守护进程。

因此：

- App 进程仍运行、窗口最小化/后台时：正常执行提醒；
- App 被用户完全退出时：不保证主动弹出 DDL 提醒；
- 用户再次打开 App 后，立即检查当前逾期任务并突出展示。

# 16. DDL 催促角色与微动效

## 16.1 情绪等级

根据任务时间紧迫程度，使用不同情绪反馈：

- 🙂 微笑；
- 😐 冷静提醒；
- 😟 着急；
- 😱 慌张；
- 🤯 火烧眉毛；
- 🤬 逾期奶凶。

## 16.2 微动效

V1 只做 Micro Animation，不开发复杂动画系统。

| 情绪 | 动效 |
|---|---|
| 微笑 | 眨眼 / 轻轻摇 |
| 冷静 | 轻微呼吸 |
| 着急 | 小幅抖动 |
| 慌张 | 快速左右看 / 小跳 |
| 火烧眉毛 | 快速抖动 / 小火苗 |
| 逾期 | 奶凶抖动 |

## 16.3 文案原则

催促文案：

- 软萌；
- 奶凶；
- 打工人语感；
- 随机多变；
- 不辱骂用户；
- 不制造强负罪感。

示例：

- 不着急，我就是来轻轻提醒一下。
- 我不催，我就是频繁出现一下。
- 那个……是不是该看我一眼了。
- 等等等等，只剩 10 分钟了！
- 到！点！了！

# 17. DDL 时间进度条

## 17.1 定义

任务设置 DDL 后显示时间进度条。

进度条表示：

> 从“计划时间”到“DDL”的时间消耗比例。

不表示实际任务完成度。

禁止使用：

> 任务完成 75%

应使用：

> 时间已走过 75%

## 17.2 默认情绪阈值

| 时间消耗 | 情绪 |
|---|---|
| 0%–40% | 🙂 从容 |
| >40%–65% | 😐 注意 |
| >65%–80% | 😟 着急 |
| >80%–95% | 😱 慌张 |
| >95%–100% | 🤯 火烧眉毛 |
| >100% | 🤬 已逾期 |

具体 UI 文案可以随机变化，但底层等级逻辑统一。

# 18. 延期

## 18.1 延期操作

任务允许延期。

延期必须填写：

1. 新 DDL；
2. 延期原因。

## 18.2 延期历史

延期不得覆盖旧记录。

示例：

```text
第一次延期
8/12 18:00 → 8/14 18:00
原因：研发接口没给

第二次延期
8/14 18:00 → 8/16 18:00
原因：测试环境不可用
```

任务详情显示：

> ↪ 已延期 2 次

## 18.3 延期后的进度

延期成功后：

- 新 DDL 生效；
- 原延期历史保留；
- DDL 时间进度根据新时间区间重新计算；
- 原 DDL 后续未触发提醒取消；
- 新 DDL 对应提醒重新计算。

# 23. 日历任务数量计算

同一任务在同一天即使同时满足：

- 计划时间在当天；
- DDL 在当天；

也只计算 1 次。

每日正式任务集合采用任务 ID 去重。

## 23.1 跨日期任务

如果：

```text
计划时间：8月12日
DDL：8月13日 21:00
```

任务可以：

- 8 月 12 日作为计划任务出现；
- 若仍未完成，8 月 13 日作为 DDL 当日任务出现。

## 23.2 逾期任务

已经逾期的任务继续出现在“今日”页面。

但不能无限增加未来每天的日历任务数量。

因此：

> 日历忙碌度只计算当天正式安排/当天 DDL 的去重任务集合。

历史逾期任务在当天页面单独显示为：

> 历史欠账

不参与当天忙碌度计算。

# 24. 日历忙碌状态

## 24.1 定义

忙碌状态描述：

> 某一天任务密度有多高。

与单个任务“紧急程度”完全独立。

## 24.2 默认忙碌模板

| 当天任务数 | 状态 | 文案 |
|---|---|---|
| 0 | 🫧 空闲 | 今天居然没事 |
| 1–2 | 🌿 松弛 | 还能摸会儿鱼 |
| 3–5 | 🙂 正常 | 正常营业 |
| 6–8 | 😵 有点忙 | 班味上来了 |
| 9–12 | 🥵 很忙 | 有点干冒烟了 |
| 13+ | 🤯 爆满 | 今天别找我 |

## 24.3 用户自定义忙碌状态

忙碌状态允许用户自行设置。

可配置：

- 档位数量；
- 每档任务数量区间；
- Emoji；
- 状态名称；
- 多条文案。

同一忙碌等级可填写多条文案，每次随机显示一条。

## 24.4 忙碌规则校验

必须满足：

- 最低档从 0 开始；
- 区间不得重叠；
- 区间不得出现数字空档；
- 最高档支持 X+；
- 状态名称不能为空；
- 最终必须覆盖所有可能任务数量。

提供：

> 一键恢复系统默认忙碌规则。

# 27. 视觉风格与品牌设计要求

## 27.1 总体风格

Work Shackle V1 整体采用：

> **国潮治愈卡通 × 当代打工人 Meme 文化**

视觉气质要求：

- 国潮；
- 卡通；
- 治愈；
- 圆润；
- 温暖；
- 轻松；
- 手作感；
- 生活感；
- 低压力；
- 年轻化；
- 有一点打工人自嘲和“淡淡的死感”。

界面可以参考“动物森友会”类产品在以下方面的设计感受：

- 圆润友好的组件轮廓；
- 低压、松弛的视觉氛围；
- 柔和留白；
- 生活化装饰；
- 轻量、治愈的微动效；
- 卡通角色与状态反馈结合。

参考的是整体视觉气质和交互感受，不得直接复制现有 IP 的角色、图形、Logo、家具、叶子元素、原版 UI 组件或其他受保护素材。

## 27.2 V1 基础配色

产品主色调采用以下配色：

### 麻纸米白

```text
#F1ECE0
```

用途：

- 主背景；

- 卡片外围背景；


用途：

- 重点文字；
- 关键状态强调；
- 导航选中态。

### 麦秆暖黄

V1 前端实现时应优先围绕以上三种主色建立 Design Token，不允许各页面随意新增大量不统一颜色。

如果任务紧急程度、DDL 或错误状态确实需要红色等告警色，可作为少量语义色使用，但不能破坏整体国潮治愈视觉体系。

## 27.3 UI 组件风格

V1 UI 应遵循：

- 避免传统 OA、ERP、Jira 式密集后台风格；
- 主要内容采用圆角卡片；
- 边框尽量柔和；
- 控件不采用冷硬科技蓝作为默认主色；
- 适度使用纸感、手作感或国潮纹理，但不能影响信息可读性；
- 任务列表保持清晰，不因装饰导致信息密度过高；
- 重要操作按钮必须明显；
- 高风险操作仍采用严肃、明确的视觉反馈；
- 微动效以轻柔、短时、低干扰为原则；
- 不做大面积闪烁、强震动、炫技式动画。

# 28. 表情包、状态角色与 Meme 设计规范

## 28.1 设计来源

Work Shackle 中用于以下场景的表情、角色动作和文案：

- 工作状态；
- 摸鱼；
- 午餐；
- 会议；
- 准备下班；
- 加班；
- DDL 提醒；
- 逾期催促；
- 日历忙碌程度；
- 今日完成；
- 空状态；

可以参考小红书、抖音、微信等平台当下年轻用户常用表情包的情绪表达方式和 Meme 语感。

参考重点包括：

- 动物人格化；
- 呆萌；
- 无奈；
- 冷漠；
- 慌张；
- 奶凶；
- 一本正经说废话；
- 打工人自嘲；
- “淡淡的死感”；
- 轻微发疯；
- 摸鱼、老板、工资、DDL、下班等常见打工语境。

但不得直接复制网络上的现成表情包、明星照片、影视截图、商业 IP 角色或来源不明确的素材。

## 28.2 原创角色原则

V1 建议采用统一的 Work Shackle 原创卡通角色体系。

同一个原创角色通过不同：

- 表情；
- 动作；
- 姿势；
- 小道具；
- 动效；

表达不同工作状态。

这样可以避免产品内部混用大量风格不统一的网络表情包，也有利于形成 Work Shackle 自己的品牌记忆。

## 28.3 推荐角色状态映射

| 场景 | 角色表现方向 |
|---|---|
| 正常工作 | 面无表情敲键盘 / 稳定搬砖 |
| 专注工作 | 戴耳机、认真盯屏幕 |
| 会议中 | 戴耳机、眼神放空 |
| 临时插单 | 突然回头 / 被吓到 |
| 被需求追杀 | 抱电脑奔跑 |
| 摸鱼中 | 偷偷探头 / 躺平 / 看手机 |
| 八卦一下 | 竖耳朵 / 探头偷听 |
| 喝点东西 | 抱杯子续命 |
| 午餐中 | 抱饭碗 / 幸福干饭 |
| 午休 | 趴桌 / 睡觉 |
| 准备下班 | 背包、偷偷看钟 |
| 加班中 | 眼神失去高光 / 头顶夜色 |
| DDL 前 60 分钟 | 轻轻提醒 / 敲桌子 |
| DDL 前 30 分钟 | 左右踱步 / 明显着急 |
| DDL 前 10 分钟 | 满头大汗 / 快速抖动 |
| DDL 到点 | 奶凶拍桌 |
| 已逾期 | 冷漠凝视 / 火冒三丈 |
| 今日完成 | 松一口气 / 小庆祝 |
| 无任务 | 躺平 / 晒太阳 / 摸鱼 |

以上为视觉方向，不要求 V1 每个状态都采用复杂动画。

## 28.4 表情与动效实现原则

V1 表情资源应优先采用本地资源随安装包发布。

可使用的技术形式在开发阶段根据成本选择，例如：

- SVG；
- WebP；
- APNG；
- Lottie；
- 本地序列帧；
- CSS / 前端轻量动画。

V1 不依赖联网实时抓取表情包。

V1 不建设在线表情包商城、表情包社区或远程素材更新系统。

## 28.5 流行趋势使用规则

“参考当下流行表情包”属于产品设计输入，而不是运行时联网能力。

流程应为：

```text
产品设计阶段人工参考当前流行趋势
↓
筛选符合 Work Shackle 气质的情绪和 Meme
↓
转化为原创角色动作和原创文案
↓
作为本地资源随版本发布
```

后续版本可以通过正常 App 版本升级替换或新增表情资源。

## 28.6 文案与表情关系

表情和文案应协同变化。

例如：

```text
DDL 前 60 分钟
角色：轻轻敲桌
文案：我不催，我就是来提醒一下。
```

```text
DDL 前 30 分钟
角色：左右踱步
文案：那个……是不是该看我一眼了。
```

```text
DDL 前 10 分钟
角色：满头大汗
文案：等等等等，只剩 10 分钟了！
```

```text
DDL 到点
角色：奶凶拍桌
文案：到！点！了！
```

同一情绪等级可以配置多条本地文案，由系统随机展示，减少重复感。

## 28.7 禁止项

V1 不应：

- 直接下载并打包来源不明的网络表情包；
- 直接复制小红书、抖音、微信中的具体表情素材；
- 使用明显属于现有商业 IP 的角色；
- 使用明星或真人照片作为默认表情；
- 使用辱骂、PUA、强焦虑式催促文案；
- 用强烈动效持续打断用户；
- 为追求“流行”而牺牲整体视觉一致性。

- 修改任务后重启电脑，再打开，修改仍存在；
- 已完成任务不会因为关闭 App 消失；
- 联系人从选择列表移除后，历史任务联系人信息仍存在；
- 延期历史不可被新延期覆盖。

## 32.2 工作目录

- 用户设置过目录后始终优先使用该目录；
- 未设置目录时 Mac 自动创建 `~/Documents/Work Shackle`；
- 未设置目录时 Windows 优先创建 `D:\Work Shackle`；
- Windows 无 D 盘时能够自动使用 Documents 兜底；
- Windows UNC / 网络路径不能作为工作目录；
- macOS 网络挂载和移动挂载目录不能作为工作目录；
- 已明确识别为云同步目录时提示用户重新选择本地目录；
- 默认目录与自定义目录均由 Rust 执行最终安全校验；
- 已设置目录被删除后，不得静默创建默认目录；
- 用户删除本地目录后重新打开，App 不崩溃。

## 32.3 任务

- 创建任务默认计划时间为当前时间；
- 默认紧急程度为“正常”；
- 任务数量不设上限；
- 一个任务最多 3 个用户提醒；
- 同一天同一任务不会在日历数量中重复统计；
- 延期必须填写原因；
- 完成任务自动保存完成时间。

## 32.4 DDL

- 设置 DDL 后显示时间进度；
- 提前 60 分钟触发提醒；
- 提前 30 分钟触发提醒；
- 提前 10 分钟触发提醒；
- DDL 到达且未完成时触发到点事件；
- 已完成任务不再触发后续 DDL 提醒；
- App 打开时可以出现前置软萌提醒；
- macOS / Windows 均有对应的应用图标提醒。

## 32.5 日历

- 支持月视图；
- 每天可以看到任务数量；
- 可以看到忙碌状态；
- 点击日期可以查看当天具体任务；
- 用户可以自定义忙碌规则；
- 忙碌规则错误时禁止保存；
- 逾期历史任务不会污染未来每一天的忙碌度。

## 32.6 加班

- 到下班时间不会自动进入加班；
- 用户必须主动开启加班；
- 可以手动结束；
- 未手动结束时次日 05:00 自动结束；
- App 中途关闭后重新打开，仍能正确补记自动结束时间；
- 同一时刻最多只有一条 active 加班记录；
- 当地时间 05:00 前的加班和工作状态归属于前一 `work_date`；
- 当地时间 05:00 起归属于当天 `work_date`；
- 任务 planned date / DDL 日期不使用 05:00 工作日规则。

## 32.7 视觉与表情

- 主要页面遵循麻纸米白、草木深绿、麦秆暖黄三色体系；
- 不出现明显传统企业后台风；
- DDL 提醒至少具备多档角色情绪反馈；
- 表情资源均为本地资源；
- 不直接打包来源不明的网络表情包；
- 不直接复刻已有商业 IP；
- 微动效不影响任务操作；
- 高风险操作不使用戏谑文案。

# 34. V1 产品范围结论

Work Shackle V1 的目标不是做一个功能很多的效率工具，而是完成一个可靠、轻量、有性格的个人工作闭环：

> **今天要干什么 → 什么快到 DDL → 什么时候下班 → 要不要加班 → 今天干完了什么 → 以后还能完整找回来。**

V1 核心特点：

1. 本地、简单、无需登录；
2. 数据长期可控；
3. 任务和 DDL 管理足够实用；
4. 下班/加班场景贴近真实打工生活；
5. 国潮治愈卡通视觉；
6. 当代打工人 Meme 语感；
7. 软萌、奶凶、年轻化的提醒体验；
8. 统一原创角色体系，避免直接复制网络或商业 IP；
9. 为未来 AI 周报、月报、年终总结提前沉淀高质量结构化数据。
