# Work Shackle 右上角页面切换实施计划

> 依据：`docs/superpowers/specs/2026-08-24-top-right-navigation-design.md`

## 视觉基线

- 颜色沿用现有纸张灰 `#efede5`、墨黑 `#111318`、荧光绿 `#cfff24`、警报橙 `#ff4b2e` 与电蓝 `#345cff`，不引入新的品牌色。
- 品牌标题继续使用现有中文展示字体，导航标签使用正文粗体，微型状态文字使用数据字体。
- 标题栏采用“左侧事务所铭牌 / 右侧在线灯与控制台”的结构。
- 签名元素是胶囊内部横向滑动的墨黑选中块，像工位控制台上的实体档位；荧光绿只用于当前档位的小型信号点。
- 自检结论：普通分段控件过于通用，因此保留 Work Shackle 的“控制台档位”语义、硬边框和状态灯，让它属于这款工位生存应用，而不是通用 SaaS 导航。

## 实施步骤

### 1. 抽出导航组件

- 新建 `src/shared/shell/AppNavigation.tsx`，定义三个页面入口、线性图标、当前页状态和切换回调。
- 保持原生 `nav`、`button` 与 `aria-current`，不增加依赖。
- 新增组件测试，覆盖可访问名称、当前状态和点击切换。

### 2. 重排标题栏与样式

- 更新 `AppShell.tsx`：把导航放入标题栏右侧控制区，保留提醒跳转到任务页的现有逻辑。
- 更新 `AppShell.css`：删除底部占位，加入滑动选中块、悬停/按下反馈、状态灯压缩和窄宽度换行规则。
- 更新 `DesignPreviewPage.tsx`，确保开发预览与真实应用使用同一导航组件。
- 在 reduced-motion 环境关闭位移与上浮动画。

### 3. 验证

- 运行导航组件测试和完整前端测试。
- 运行 TypeScript 与 Vite 构建。
- 检查正在运行的 Tauri 应用热更新结果；必要时在常用宽度下截屏检查标题、状态与导航是否拥挤。

## 变更边界

- 不修改页面业务状态、提醒跳转协议或 Rust 后端。
- 不覆盖工作区内其他未提交改动。
- 不引入路由库、图标库、在线字体或远程资源。
