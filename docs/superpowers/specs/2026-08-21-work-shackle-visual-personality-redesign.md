# Work Shackle「严肃排版，内容发疯」视觉与交互重设计

> 状态：视觉方向已确认，待书面复核  
> 日期：2026-08-21  
> 范围：应用外壳、今日页、任务页、设置页、提醒窗口及其公共组件

## 1. 目标

将当前偏通用的效率工具界面改造成面向当代打工人的「工位生存系统」。产品不催促用户变得更高效，而是准确呈现工作进度，并在真实工作事件发生时，用自我调侃的方式替用户说出内心话。

一句话原则：**严肃排版负责把事情说清楚，打工马负责在关键时刻发疯。**

成功标准：

1. 用户不看产品名，也能从版式、文案和反馈认出这是 Work Shackle。
2. 核心操作名称清楚，幽默不遮蔽时间、状态、优先级和错误原因。
3. 疯感来自真实状态变化，不依靠常驻弹幕或无意义装饰。
4. 页面具有截图分享的记忆点，但长期使用不会持续吵闹。

## 2. 已确认方向

- 情绪强度采用「明显有梗」：高于克制点缀，低于全屏持续发疯。
- 表情体系采用原创打工马，不直接使用小红书、微信或其他平台的受保护表情包/IP。
- 视觉参考采用混合方案：
  - 以黑色仪表盘式结构承载信息；
  - 借用报纸的高密度编辑排版和大字标题；
  - 借用小票、条码、印章、票号和贴纸作为局部细节。
- 疯感以事件触发为主：临时插活、任务逾期、完成任务、老板继续追加、理论下班、进入加班。
- 现有业务能力和数据模型不重写；本轮集中改造前端呈现、状态反馈和公共视觉语言。

## 3. 视觉系统

### 3.1 气质

整体是「一本正经的工位事故报告」：结构严谨、信息锐利、措辞逐渐失控。参考物不是通用 SaaS，而是报纸头版、工位通行证、便利店小票、系统警报和群聊里的真实内心。

禁止：

- 大面积玻璃拟态、柔和渐变和科技光晕；
- 每张卡片都倾斜、描边、贴纸化；
- 无状态依据的随机段子；
- 用玩笑替代明确错误和关键操作名称；
- 页面整体持续摇晃、弹跳或闪烁。

### 3.2 色彩令牌

| 角色 | 色值 | 使用规则 |
|---|---|---|
| 墨黑 | `#111318` | 主文字、深色舞台、边框 |
| 纸张灰 | `#EFEDE5` | 应用背景 |
| 抬升纸白 | `#FBFAF5` | 内容卡片、表单区域 |
| 电光蓝 | `#345CFF` | 当前状态、信息高亮 |
| 荧光绿 | `#CFFF24` | 下班、完成、可恢复状态 |
| 警报红 | `#FF4B2E` | 插活、逾期、需要处理的异常 |
| 辅助灰 | `#74736D` | 说明、时间元数据 |

一块组件只设一个主强调色。荧光绿不用于普通装饰，警报红不用于中性按钮。

### 3.3 字体与排版

- 中文显示：系统黑体栈，高字重、紧字距，用于大标题和状态结论。
- 正文：系统无衬线，保持正常字距和可读行高。
- 时间、票号、百分比：等宽或窄体数据字体栈，使用等宽数字。
- 主倒计时是首屏最大文字；状态结论第二；任务名称第三；辅助说明不得与状态抢层级。
- 使用真实结构性元素：票号标识一条记录，条码结束一组小票内容，印章表达已发生的状态，而不是纯装饰。

### 3.4 形状与质感

- 应用外壳使用 22–24px 圆角，内容卡片 14–18px。
- 主舞台不描边，使用纯墨黑底；浅色卡片使用 1–2px 深色或灰色边框。
- 贴纸、警报和反应卡允许 1–4 度轻微旋转与硬阴影。
- 同一视口最多同时出现两个倾斜元素，防止页面失去秩序。

## 4. 页面架构

### 4.1 应用外壳

顶部保留品牌与实时状态，品牌改为更像刊头：

- `精神状态事务所`
- `OFFICE SURVIVAL SYSTEM`
- 右侧实时状态示例：`人还在线 · 灵魂稍后补发`

底部三段导航保持稳定位置和明确命名：`今日状态`、`任务现场`、`生存设置`。激活项使用墨黑底，不用图标堆叠。

### 4.2 今日页

桌面端采用两列四区布局：

```text
┌──────────────────────────────┬────────────────────┐
│ 黑色下班倒计时舞台             │ 今日精神广播          │
│ 倒计时 / 进度 / 打工马 / 事件贴纸│ 状态结论 / 反应卡      │
├──────────────────────────────┼────────────────────┤
│ 今日待办小票                   │ 今日工位使用证         │
│ 任务列表 / 票号 / 条码          │ 班表 / 提醒 / 内心提示  │
└──────────────────────────────┴────────────────────┘
```

移动端顺序：倒计时舞台 → 精神广播 → 今日任务 → 工位使用证。

倒计时舞台包含：

- 阶段标题，例如 `距离下班越近，灵魂越完整`；
- `HH:MM:SS` 主倒计时；
- 工作进度、班味浓度和起止时间；
- 打工马沿轨道前往「下班」；
- 仅在有事件时出现的贴纸，例如 `老板正在输入…`。

精神广播包含：

- 当前进度或状态百分比；
- 一条结论，例如 `表面稳定，内存告急`；
- 一条事实说明；
- 一张打工马反应卡，例如 `检测到临时插活 / 建议先装死 3 秒`。

任务区域采用小票式层级，但保留现有任务选择、详情、完成和延期行为。主要按钮仍叫 `新任务`；只允许在辅助说明中使用 `领取新福报` 等梗。

班表区域明确显示当天生效的开始和结束时间、提醒计划与保存状态。幽默提示必须与实际规则一致，例如：`今天修改的下班时间，不代表老板认可。`

### 4.3 任务页

- 页面标题、筛选器、日历和任务列表共享报纸/票据层级。
- 日历保持可扫描，不在每个日期格塞表情。
- 忙碌程度使用颜色和简短状态词；极忙日期可触发小型打工马反应，不改变日期点击行为。
- 空状态、筛选无结果和完成反馈采用不同文案，不复用同一段子。

### 4.4 设置页

- 设置页视觉更安静，定位为「工位使用说明」。
- 各设置分区使用清晰标题、编号仅在有顺序时出现。
- 保存动作、验证错误和依赖关系保持直白；梗仅出现在区块说明与成功反馈。

### 4.5 提醒窗口

- 提醒窗口是疯感最强的独立触点。
- 结构为：时间/类型 → 任务事实 → 原创打工马反应 → 两个明确动作。
- DDL 越近，颜色、字重和打工马表情逐级升级；窗口位置和尺寸不跳动。
- 到点不自动替用户完成任务或切换状态。

## 5. 事件驱动的疯感

组件通过现有业务状态选择对应的视觉与文案，不引入随机反馈。每次事件只显示一个主要反应。

| 事件 | 视觉反应 | 文案示例 |
|---|---|---|
| 页面正常工作 | 无额外贴纸 | `人还在线 · 灵魂稍后补发` |
| 新增任务 | 轻量小票反馈 | `新福报已入账` |
| 临时插活 | 红色倾斜警报 + 瞳孔地震马 | `检测到临时插活` |
| 完成任务 | 荧光绿印章 + 假笑马 | `任务 -1，功德 +1` |
| 列表完成后又新增 | 反差反应卡 | `命运立刻补了一项` |
| 任务逾期 | 红色票号/标签 + 石化马 | 直接显示逾期时长，再补一句自嘲 |
| 理论下班 | 荧光绿终点 + 狂奔马 | `今日工位使用权到期` |
| 加班开始 | 颜色降饱和 + 石化马 | `下班失败，已续费` |
| 保存失败 | 稳定错误区域 | 明确错误原因和重试动作，不玩梗 |

反应显示后不遮挡主要内容；重要弹层必须可关闭、可键盘操作，并避免同一事件重复触发。

## 6. 原创打工马

保留现有半写实奔跑马作为进度角色，补充五种可复用反应状态：

1. 职业假笑：正常工作、成功反馈。
2. 缓缓闭眼：等待反馈、低能量。
3. 瞳孔地震：临时插活、DDL 接近。
4. 下班狂奔：进入最后阶段、确认下班。
5. 加班石化：进入加班、严重逾期。

角色图必须原创、本地化、透明背景。界面中由 CSS 控制尺寸、位置与轻量进入动效，不对整张图片做持续弹跳。`prefers-reduced-motion` 下使用静态姿态。

## 7. 组件边界与数据流

### 7.1 公共呈现组件

- `AppShell`：品牌刊头、页面容器、底部导航。
- `Card`、`Button`、`Input`、`Modal`、`Drawer`：统一基础视觉、焦点和禁用状态。
- 新增 `StatusSticker`：展示基于状态的贴纸或印章，只接收明确的 tone、label 和可选旋转级别。
- 新增 `WorkhorseReaction`：根据 reaction 枚举呈现打工马图片、标题和说明。
- 新增 `ReceiptMeta`：票号、时间、条码等结构性元数据，避免页面重复拼装。

### 7.2 状态选择

业务 hooks 继续提供任务、倒计时、工作状态和提醒数据。页面层把数据交给纯函数映射为显示状态：

```text
业务数据 → 显示状态选择器 → tone / headline / reaction / sticker → 纯呈现组件
```

显示状态优先级：

```text
需要处理的错误 > 待确认决定 > 逾期/临时插活 > 加班/已下班 > 特殊工作状态 > 普通进度
```

状态选择器必须可单元测试，不能把时间判断和随机文案散落在 JSX 中。

## 8. 错误、加载与空状态

- 加载：使用与最终布局同尺寸的纸张/墨黑骨架，禁止整页跳动。
- 错误：说明发生了什么以及如何恢复；按钮统一为 `重试`、`重新保存` 等准确动作。
- 空任务：`暂时没人往你工位扔活 / 看起来很清闲，建议保持低调。`
- 筛选无结果：说明当前筛选条件，并提供清除筛选动作。
- 保存成功：使用短暂印章或反应卡，不弹阻断式模态框。

## 9. 可访问性与响应式

- 正文、标签和按钮达到 WCAG AA 对比度；荧光绿文字不直接置于白底。
- 所有倾斜元素的可点击区域保持水平矩形，避免影响命中。
- 动画不承担唯一信息，打工马装饰图使用正确的无障碍隐藏；状态由文本同步表达。
- 支持键盘焦点、屏幕阅读器标签和 `prefers-reduced-motion`。
- 760px 以下改为单列；480px 以下缩小倒计时而不截断；不允许水平滚动。

## 10. 测试与验收

### 10.1 自动化测试

- 显示状态选择器覆盖普通、插活、逾期、完成、下班和加班。
- 打工马反应枚举与素材映射完整。
- 关键按钮文案和无障碍标签不因装饰文案改变。
- 倒计时、工作进度和班表修改继续通过现有测试。
- 今日页、任务页、设置页和提醒窗口的主要状态渲染测试更新。
- TypeScript 构建、Vitest 全量测试和 Tauri 配置检查通过。

### 10.2 视觉验收

至少检查桌面宽屏、窄桌面、平板和手机四个尺寸，并覆盖：

- 正常工作；
- 临时插活或逾期；
- 无任务；
- 理论下班待确认；
- 加班；
- 加载与错误。

验收要求：

1. 首屏一眼可见倒计时、当前状态和第一组任务。
2. 视觉上能明确辨认报纸层级、票据细节与事件贴纸。
3. 页面静态时有秩序，事件发生时有明显反差。
4. 任何梗都不改变关键动作的含义。
5. 打工马不是 emoji 占位符，五种反应清晰可辨。
6. 所有页面共享同一套视觉语言，而不是只改今日页。

## 11. 实施范围

本轮包含：

- 视觉令牌、公共组件和应用外壳改造；
- 今日页完整重排与状态反馈；
- 任务页、设置页、提醒窗口统一视觉；
- 原创打工马反应素材及状态映射；
- 文案集中管理；
- 自动化测试、响应式和真实页面视觉检查。

本轮不包含：

- 新增任务业务字段或后端表结构；
- 社交分享、表情包下载或真实平台内容接入；
- 随机弹幕、积分排行、复杂成就系统；
- 引入在线字体、CDN 图片或第三方表情包。
