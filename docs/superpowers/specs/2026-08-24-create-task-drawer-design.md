# 新建任务抽屉交互设计

## 背景

当前“新建任务”使用居中弹窗，而修改任务使用右侧抽屉，两种相近操作的空间模型不一致。同时，“任务”页面的定位调整为历史任务查看，不再承担新建任务入口。

## 目标

- “今日”页面保留“+ 新任务”入口，点击后从右侧展开新建任务抽屉。
- 新建抽屉沿用当前新建表单的全部能力与校验规则。
- 创建成功后自动关闭抽屉并刷新今日待办列表。
- “任务”页面删除新建入口和创建相关状态，仅保留历史查看与任务详情抽屉。
- 不改变现有任务创建数据结构、后端调用和错误文案。

## 组件设计

### CreateTaskDrawer

将现有 `CreateTaskModal` 替换为 `CreateTaskDrawer`。组件继续负责：

- 表单初始化与每次打开时重置。
- 任务名称、备注、计划时间、DDL、紧急程度和联系人的录入。
- 最多三个自定义提醒的增删与校验。
- 调用 `createTask`、映射错误并向页面报告创建成功。

视觉容器由 `Modal` 改为共享的 `Drawer`。抽屉标题为“新建任务”，底部操作为“取消”和“创建任务”；提交期间禁用关闭型操作和重复提交。表单内容允许在抽屉主体内纵向滚动，底部操作区保持可见。

### TodayPage

“+ 新任务”继续控制本地打开状态，但渲染 `CreateTaskDrawer`。创建成功后执行 `loadTodayTasks()`，组件随后通过现有 `onClose` 关闭抽屉。

任务详情仍使用 `TaskDrawer`，新建抽屉和详情抽屉由不同状态控制，同一时间只会由用户操作打开其中一个。

### TasksPage

删除页面中的“新建任务”按钮、`createOpen` 状态、`CreateTaskModal` 引用及创建成功刷新逻辑。页面继续支持列表、日历、历史任务筛选和点击任务后打开详情抽屉。

当历史列表为空时，保留现有空状态，不增加引导新建任务的按钮。

## 数据流

1. 用户在“今日”页面点击“+ 新任务”。
2. 页面打开 `CreateTaskDrawer`，表单恢复默认值。
3. 用户提交后，组件校验输入并调用现有 `createTask` 服务。
4. 成功时先通知页面刷新今日任务，再关闭抽屉。
5. 失败时保持抽屉打开，在表单内显示现有映射错误，用户可修正后重试。

## 测试与验收

- 组件测试确认新建任务渲染为 `Drawer`，不再渲染 `Modal`。
- 确认每次打开都会重置表单，创建成功触发 `onCreated` 和 `onClose`。
- 页面源码回归测试确认“今日”页使用 `CreateTaskDrawer`。
- 页面源码回归测试确认“任务”页不存在新建入口、创建组件或创建状态。
- 完整前端测试和生产构建通过。
- App 中点击“今日”页的“+ 新任务”时，右侧抽屉展开；创建后抽屉关闭且列表更新。
