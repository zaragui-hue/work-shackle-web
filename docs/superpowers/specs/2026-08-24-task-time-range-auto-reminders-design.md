# 任务时间段与自动提醒设计

## 背景

新建任务目前分别填写计划时间和可选 DDL，并允许设置自定义提醒。新的工作流要求用户直接选择完整时间段，由系统根据任务进度自动生成提醒；提醒弹窗同时升级为与现有多巴胺粗野主义界面一致的“反骨工票”。

## 目标

- 新建任务改为必填的开始时间与完成时间，精确到分钟。
- 紧急程度默认选择“正常 · 该干还是得干”。
- 对接人改为自由输入姓名，非必填。
- 新建任务删除自定义提醒入口，由系统自动计算三档提醒。
- 提醒节点为时间过半、剩余四分之一和剩余一小时；完成时间到点不额外提醒。
- 弹窗采用桌面端 A 方案“反骨工票”，班味、嘲讽感和多巴胺视觉显著增强。
- 不设计手机端适配。

## 新建任务表单

### 时间段

“计划时间 / DDL”替换为一个“任务时间段”区块：

- 开始时间必填，默认当前本地时间并截断到分钟，秒保存为 `00`。
- 完成时间必填，默认当天 `18:00`；当前时间已经超过 `18:00` 时，默认次日 `18:00`。
- 两个控件使用桌面端 `datetime-local`，步长为 60 秒。
- 完成时间必须严格晚于开始时间，否则在时间段区块内提示并阻止提交。

现有数据库字段继续使用 `planned_at_ms` 和 `deadline_at_ms`，分别表示开始与完成时间；不新增任务表字段。

### 紧急程度

默认值为优先级 `2`：`🙂 正常 · 该干还是得干`。现有五档优先级及选项文案保持不变。

### 对接人

新建表单不再渲染联系人选择与管理器，改为一个普通文本输入：

- 标签为“对接人”。
- 非必填，空白值不提交联系人。
- 非空值通过现有 `contactSnapshot` 提交。
- 后台继续按姓名查找或创建联系人，因此使用过的姓名仍可用于历史筛选和后续数据展示。

任务详情页已有联系人编辑交互不在本次范围内。

### 自定义提醒

新建抽屉删除“自定义提醒”区块、添加/移除按钮、表单数组和相关前端校验；创建请求不再发送自定义提醒。

已有任务中已经保存的自定义提醒继续按照原时间触发，不删除、不迁移，避免静默丢失用户既有设置。

## 自动提醒引擎

### 节点计算

设开始时间为 `S`、完成时间为 `E`、总时长为 `D = E - S`：

- 时间过半：`S + D × 50%`
- 剩余四分之一：`S + D × 75%`
- 剩余一小时：`E - 1 小时`

只保留严格满足 `S < trigger < E` 的节点。时间计算使用毫秒，最终触发时间按分钟对齐。

系统提醒种类替换为：

- `progress_half`
- `quarter_remaining`
- `one_hour_remaining`

旧的 `ddl_60 / ddl_30 / ddl_10 / ddl_due` 不再为新调度生成；完成时间到点不创建系统提醒。

### 重合与顺序

- 节点按触发时间排序。
- 同一分钟出现多个节点时合并为一个节点，并保留语义上更紧急的种类，优先级为：剩余一小时 > 剩余四分之一 > 时间过半。
- 短任务产生早于或等于开始时间的“剩余一小时”节点时直接跳过。

### 休眠与补发

App 恢复运行时，如果同一任务已经错过多个未处理节点，只展示当前最紧急的一次。其他错过节点同时写入系统提醒日志作为已处理，避免后续循环连续补弹。

不同任务在同一轮触发时继续沿用现有主提醒加额外任务数量的合并机制。

### 延期

任务延期后使用原开始时间与新完成时间重新计算。系统提醒日志继续按完成时间快照去重，因此新完成时间会产生一组新的提醒节点，旧快照不会阻止新节点触发。

## 提醒弹窗：A「反骨工票」

### 视觉结构

- 顶部粗黑票据栏：`WORK ALERT / 工位警报` 与任务编号。
- 中部使用蓝、橙、黄、红、奶油色，配粗黑描边、硬阴影与轻微旋转。
- 展示超大进度数字、任务名称、阶段标签、倾斜印章和嘲讽文案。
- 三档状态逐级升级：过半以蓝橙为主，剩四分之一转橙红，剩一小时使用红黄最高警戒。
- 动画只用于票据弹入、印章落下和轻微抖动，并遵循 `prefers-reduced-motion`。
- 仅适配桌面提醒窗口，不增加手机端断点。

### 文案

- 时间过半：`工期已烧掉一半，你的进度还在加载企业文化。`
- 剩余四分之一：`只剩四分之一。建议停止同步上下文，上下文已经开始同步你的死线。`
- 剩余一小时：`最后一小时。现在开始努力，至少能显得之前不是纯摸鱼。`

重合节点使用合并后更紧急种类的标签、颜色和文案。

### 操作

- 次要操作：`我知道了，别催`，关闭提醒窗口。
- 主要操作：`去把坑填上 →`，打开对应任务详情并关闭提醒窗口。
- 现有附加任务数量提示保留，但文案与票据视觉统一。

## 错误处理

- 开始或完成时间为空时显示字段错误。
- 完成时间不晚于开始时间时显示“完成时间必须晚于开始时间”。
- 对接人空白字符按未填写处理；后台联系人解析失败时沿用任务错误映射。
- 无有效系统节点的短任务可以正常创建，不视为错误。
- 提醒窗口打开任务失败时沿用现有降级行为，关闭提醒窗而不阻断提醒日志处理。

## 测试与验收

### 前端

- 默认开始时间为当前分钟，默认完成时间为当天或次日 `18:00`。
- 时间输入精确到分钟，完成时间必须晚于开始时间。
- 默认优先级为 `2`。
- 对接人自由输入通过 `contactSnapshot` 提交，空白不提交。
- 新建抽屉不包含自定义提醒 UI 或提醒数组。
- 三档提醒文案、颜色状态和两个操作正确。

### Rust

- 覆盖长任务的三个节点计算。
- 覆盖短任务跳过开始前节点。
- 覆盖同一分钟节点合并及紧急度优先级。
- 覆盖恢复运行只补发最紧急节点并处理其余过期节点。
- 覆盖延期后按新完成时间重新计算。
- 覆盖旧自定义提醒仍可触发。
