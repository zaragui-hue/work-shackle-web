# Work Shackle 右上角页面切换设计

## 目标

将当前页面底部的主导航移动到应用标题栏右上角，并把它升级为更年轻、直观、一次点击即可完成切换的胶囊式导航。改动只影响主导航及标题栏布局，不改变三个页面的业务逻辑、页面名称或数据状态。

## 交互方案

- 标题栏从左到右排列品牌区、在线状态和页面导航。
- 导航始终提供“今日”“任务”“设置”三个入口；桌面宽度下全部可见。
- 当前页面使用深色滑动选中块，文字为白色，并保留荧光绿作为状态强调色。
- 鼠标悬停时按钮轻微上浮；切换时选中块做短促、克制的位移动效。
- 点击入口立即切换页面，不增加下拉菜单或二次确认。
- 在线状态从完整文案胶囊压缩为橙色状态点和短标签，避免标题栏拥挤。

## 组件与状态

- 继续由 `AppShell` 持有当前 `tab` 状态和提醒跳转逻辑。
- 导航仍使用语义化 `nav` 与原生 `button`，不引入新依赖。
- 每个入口增加简洁线性图标；可见标签缩短为“今日”“任务”“设置”，无障碍名称保留完整含义。
- 删除底部导航占位，使内容区域自然使用释放出的纵向空间。

## 响应式规则

- 宽窗口：显示图标与三个短标签。
- 中等宽度：在线状态只保留状态点，导航保持完整，优先保证页面切换可发现。
- 窄窗口：品牌信息占据第一行，导航在标题区域第二行右对齐；不恢复到底部，也不隐藏到菜单中。
- 导航按钮保持足够的点击面积，标签不换行。

## 动效与无障碍

- 动效持续时间控制在约 160–220ms，不使用大幅弹跳或连续动画。
- 键盘用户可以 Tab 聚焦每个入口，焦点轮廓清晰可见。
- 当前页面同时通过视觉样式和 `aria-current="page"` 表达。
- 系统开启“减少动态效果”时，关闭滑动、上浮和回弹效果。

## 验收标准

1. 底部不再出现页面切换按钮，右上角可以一次点击切换三个页面。
2. 当前页面状态清晰，悬停、按下和键盘焦点状态均可辨认。
3. 提醒触发后跳转到任务页的既有行为不受影响。
4. 1024×700 的应用最小窗口和常见窄窗口下，导航不溢出、不遮挡品牌。
5. TypeScript 构建和现有相关测试通过；新增针对导航标签、当前状态和切换行为的测试。

## 非目标

- 不引入路由库、下拉菜单或页面切换手势。
- 不重做页面内容、品牌配色或应用标题栏以外的组件。
- 不修改任务、提醒、设置等业务数据流。
