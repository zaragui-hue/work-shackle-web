# 任务详情抽屉自动保存与行动接头设计

## 背景

任务详情抽屉目前展示自定义提醒，并依赖底部“保存”按钮统一提交表单。延期按钮又位于任务管理区域，和进度、主状态混在一起。用户希望抽屉更轻、更直接：字段编辑后自动保存，延期作为任务级动作进入底部操作行，同时让对接人字段带有“特务接头”的轻度戏剧感。

## 目标

- 删除任务详情抽屉中的自定义提醒展示，不修改提醒数据或后端能力。
- 新建与编辑任务的开始、完成时间继续共用日期时间选择器，支持跨天并精确到分钟。
- 对接人保持自由输入，不提供联系人选择，使用“秘密接头”风格的字段文案。
- 编辑任务时取消独立保存按钮，改为可靠的字段级自动保存。
- 延期按钮从任务管理区移到抽屉底部，与取消任务、完成任务并列。
- 保留进度条、主状态、延期记录和终态只读行为。

## 方案选择

采用字段级自动保存：文本与日期时间字段失焦保存，紧急程度和主状态选择后立即保存。相比整表防抖保存，该方案不会在用户输入到一半时提交；相比关闭抽屉时保存，反馈更及时，也不会因为意外关闭丢失修改。

## 核心字段

`TaskCoreFields` 继续由新建与编辑抽屉共用。开始时间和完成时间均使用 `datetime-local`，`step=60`，即日期与时间组合选择、分钟精度为 1 分钟。

对接人字段不接入联系人选择器，标签和提示统一调整为：

- 标签：`🕵️ 接头人`
- 占位提示：`输入本次行动的秘密联络人`

新建任务和编辑任务同时使用该文案，保持共享字段一致。

## 自动保存

详情抽屉使用 React Hook Form 的校验与脏字段状态管理：

- 任务名称、备注、开始时间、完成时间、接头人在失焦时触发保存。
- 紧急程度和主状态在值发生改变后触发保存。
- 只在表单校验通过且当前值与最近成功保存值不同时调用 `updateTask`。
- 保存请求串行执行。保存过程中产生的新修改在当前请求完成后继续保存最新快照，不允许较旧响应覆盖较新输入。
- 保存成功后调用 `onChanged` 刷新外部任务列表，但不重新拉取并重置当前表单，避免打断焦点或覆盖尚未保存的修改。
- 保存失败时保留输入值，显示现有任务错误文案；下一次失焦或选择变更可以重试。

抽屉在字段区与任务管理区之间显示一行轻量状态：

- 有请求进行中：`正在传递情报…`
- 最近一次保存成功：`情报已同步`
- 尚未产生保存动作：不显示。

终态任务的字段继续全部禁用，不触发自动保存。

## 抽屉布局

抽屉主体按以下顺序排列：

1. 任务名称与备注。
2. 任务时间段：开始时间、完成时间。
3. 紧急程度。
4. `🕵️ 接头人`。
5. 自动保存状态。
6. 任务管理：时间进度条、主状态。
7. 延期记录（存在时显示）。
8. 终态只读提示（仅终态显示）。

删除自定义提醒整个区块。任务管理标题行不再包含延期按钮。

非终态任务的底部操作从左到右为：

1. `取消任务`
2. `申请延期`（只有任务存在完成时间时显示）
3. `完成任务`

不显示保存按钮。三个按钮具有不同层级：取消任务使用次级样式，申请延期使用小麦色强调，完成任务使用主操作样式。

## 错误与边界

- 完成时间必须晚于开始时间；校验失败时不发请求，并在完成时间字段下显示提示。
- 任务名称为空、备注或接头人超长时不发请求并显示字段错误。
- 自动保存期间禁用任务级底部动作，防止保存和完成、取消、延期同时发生。
- 关闭抽屉时若存在已通过校验但尚未开始的排队保存，保存队列继续完成；组件卸载后不再更新本地状态。
- 延期成功后重新加载任务详情，以取得新的完成时间和延期记录。

## 测试与验收

- 核心字段测试确认两个日期时间控件都是 `datetime-local` 且 `step=60`。
- 对接人测试确认新建和详情抽屉都显示新标签与占位提示，且不存在联系人选择器。
- 详情测试确认文本失焦触发一次保存，下拉变化立即保存，相同值不重复保存。
- 详情测试确认没有保存按钮和自定义提醒区块，延期按钮位于底部操作区。
- 自动保存失败、校验失败、连续修改和终态只读均有覆盖。
- 完整前端测试与生产构建通过。
