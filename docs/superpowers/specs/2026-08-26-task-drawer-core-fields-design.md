# 任务详情抽屉核心字段统一设计

## 背景

当前新建任务抽屉包含“任务名称、备注、开始时间、完成时间、紧急程度、对接人”六项核心字段，而点击任务打开的详情抽屉只允许修改 DDL、主状态、备注和联系人。用户在创建与修改任务时面对两套字段结构，既难以理解，也无法在详情中补改名称、开始时间和紧急程度。

## 目标

- 点击任意任务后，详情抽屉顶部使用与新建任务一致的核心字段、标签和排列顺序。
- 新建与编辑共用同一个核心字段视图，后续字段调整不会再次漂移。
- 详情抽屉继续保留进度、主状态、延期、提醒、延期记录以及完成/取消操作。
- 已完成或已取消任务仍为只读，但展示相同的核心字段。
- 不修改后端任务数据结构或 IPC 契约。

## 方案选择

采用“共享核心字段组件 + 独立管理区”。另有两个可行方案：只在详情抽屉复制一套表单，改动较小但容易再次漂移；合并新建与详情抽屉，复用最彻底但会把创建、更新、延期和终态操作耦合在一个大组件中。本方案在一致性与改造风险之间更平衡。

## 界面结构

### 核心字段区

新建和详情抽屉共同渲染 `TaskCoreFields`，顺序固定为：

1. 任务名称
2. 备注
3. 任务时间段：开始时间、完成时间
4. 紧急程度
5. 对接人

字段沿用新建任务的文案、控件和校验提示。任务时间段继续使用带标题的强调容器。详情抽屉的标题改为“任务详情”，避免任务名称同时出现在抽屉标题和可编辑输入框中。

### 任务管理区

详情抽屉在核心字段下方保留独有能力：

- 时间进度条，用当前开始时间与完成时间计算。
- 延期按钮，仍通过延期弹窗记录延期原因；只有非终态且存在完成时间时显示。
- 主状态选择。
- 延期记录。
- 自定义提醒列表。
- 底部的取消任务、完成、保存操作。

管理区与核心字段区使用明确的视觉分组。“完成时间”取代原来的 `DDL` 输入，延期按钮放在进度管理区域，不再形成第二个重复的日期输入。

## 数据与校验

详情表单增加 `title`、`startAt`、`endAt`、`priority` 和 `contactName`，并与创建表单复用核心字段校验规则：

- 任务名称去除首尾空格后必填。
- 备注最多 2000 字。
- 开始时间和完成时间必填，完成时间必须晚于开始时间。
- 紧急程度为 1 到 5 的整数。
- 对接人最多 100 字。

加载任务详情时，将 `plannedAtMs` 和 `deadlineAtMs` 转换为本地日期时间字符串，将联系人快照填入对接人。保存时调用现有 `updateTask`，一次更新名称、备注、开始时间、完成时间、紧急程度、主状态和联系人快照。

详情中手工修改对接人后，保存联系人快照，并清除旧的 `contactId`，避免联系人名称与联系人记录指向不同对象；未修改时保留原 `contactId`。这保留了已有任务的联系人关联，同时让编辑控件与新建任务保持一致。

## 状态与错误处理

- 抽屉每次打开或任务 ID 改变时重新加载详情并重置表单。
- 保存成功后刷新调用页面的任务列表，再重新加载详情。
- 保存失败保持抽屉打开，在表单顶部显示现有错误映射文案。
- 终态任务禁用全部核心字段、主状态和延期操作，并继续显示历史记录。

## 验收标准

- 点击任务后可看到与新建任务相同的六项核心字段和相同顺序。
- 修改名称、备注、开始时间、完成时间、紧急程度和对接人后可一次保存。
- 完成时间不晚于开始时间时阻止提交并显示校验提示。
- 进度、延期、主状态、提醒、延期记录和底部任务操作仍可用。
- 完成或取消任务的字段只读。
- 相关单元测试、完整前端测试和生产构建通过。
