# 今日待办自动开工与打工马播报设计

## 1. 目标

让新建任务在到达计划开始时间后，自动从“未开始”变为“进行中”，并在今日待办中用强反差的状态盖章与打工马播报表达这次变化。

本次采用已确认的视觉方向：撞色盖章负责稳定展示状态，卡片底部的打工马播报条负责短暂反馈状态变化。

## 2. 状态规则

- 自动变化只有一条：`未开始 → 进行中`。
- 触发条件为当前设备时间大于或等于任务的计划开始时间。
- `暂停`、`等别人`、`已完成`、`已取消`均视为人工或终态，不被自动逻辑覆盖。
- 自动变化写入现有任务状态字段并持久化到本地数据库，不只是在页面上临时推导显示。
- 修改任务计划开始时间后，若任务仍为“未开始”且新时间已经到达，则在下一次状态协调时进入“进行中”；已经进入其他状态的任务不回退。
- 应用关闭期间错过的开始时间，会在下次启动或读取今日任务时补偿更新，但不批量播放旧播报。
- 自动逻辑不负责完成任务，也不根据 DDL 自动取消、暂停或结束任务。

## 3. 数据与触发流程

### 3.1 后端作为状态真源

在任务仓储增加按时间批量更新到期任务的操作，只更新同时满足以下条件的记录：

- `status = 'not_started'`
- `planned_at_ms <= now_ms`

更新结果为 `status = 'in_progress'`，同时更新 `updated_at_ms`。条件更新保证并发刷新、重复调用和应用恢复时保持幂等，也避免覆盖用户刚刚选择的暂停或等待状态。

任务服务在查询今日任务前执行一次协调。这样应用启动、页面重载或从休眠恢复后，都能修正错过的状态变化。创建任务仍按现有流程先落库；创建完成后今日列表刷新会立即协调已经到点的任务。

### 3.2 今日页精确刷新

今日页从当前“未开始”任务中找到最近的计划开始时间，并设置一次性计时器。计时器到点后重新查询今日任务，查询过程由后端完成持久化更新。任务集合或计划时间变化时重新计算计时器，页面卸载时清理。

计时器只负责及时触发刷新，后端协调负责正确性。系统休眠、计时器延迟或应用关闭不会导致永久漏更。

### 3.3 识别实时变化

今日页保留刷新前后的任务状态快照。只有任务在当前页面会话中从“未开始”实际变为“进行中”时，才触发该卡片的打工马播报。首次加载时已经由后端补偿为“进行中”的任务只显示最终盖章，不播放播报，避免启动时多张卡片同时弹出历史反馈。

同一轮有多项任务同时开工时，各卡片可各自显示播报，但不播放声音，也不抢占焦点。

## 4. 今日待办卡片设计

### 4.1 稳定状态盖章

- “未开始”使用低饱和灰白印章，保持可读但降低存在感。
- “进行中”使用荧光绿撞色印章，主文案为“开工了”，辅助信息显示“进行中”。
- 自动切换后的印章旁显示小字“计划时间 · 自动”，让用户知道变化来源。
- 暂停、等别人、已完成、已取消继续使用明确文字，不伪装成自动状态。
- 印章位于卡片右上区域，任务标题预留安全宽度；长标题换行时不被覆盖。

### 4.2 打工马底部播报条

实时自动切换时，先播放一次短促盖章反馈，约 `120ms` 后在该卡片底部展开播报条：

- 高度约 `48px`，使用黄色背景、黑色粗边框和打工马头像。
- 默认文案：“打工马播报：时间到了，活自己醒了。”
- 播报条持续约 `4s` 后自动收起，不长期增加列表高度。
- 播报出现时只推动该卡片高度，不覆盖标题、DDL、进度条、元数据或点击区域。
- 用户点击播报条可提前收起；点击卡片其他区域仍打开任务详情。
- 卡片被移出列表或页面离开时取消对应收起计时器。

播报只表达已经发生的自动状态变化，不提供撤销或状态切换按钮。用户仍可在任务详情中手动修改状态。

### 4.3 动效与无障碍

- 盖章动效使用短促缩放与轻微旋转，播报条使用高度和透明度过渡。
- 遵循 `prefers-reduced-motion`：减少动态效果时不播放位移、缩放或旋转，只立即更新文字并静态显示播报条。
- 状态变化通过文本同步表达，颜色和动画不是唯一信息来源。
- 实时播报使用克制的 `aria-live="polite"`，不移动键盘焦点，不播放音效。
- 手机窄屏下播报文案允许省略为“时间到了，自动开工。”，打工马与状态文字仍完整保留。

## 5. 组件边界

- 后端任务仓储：负责条件批量更新与数据库幂等性。
- 后端任务服务：负责在今日任务查询前协调到期状态。
- 今日页状态计时器：负责在最近的计划时间到达时刷新。
- 今日任务板：负责比较前后状态并标记本会话中的实时变化。
- 今日任务卡：负责盖章、播报条、收起行为和无障碍反馈。
- 任务详情与历史页：继续消费持久化后的标准任务状态，不新增另一套“显示状态”。

不把时间判断散落在卡片 JSX 中，也不新增独立的自动状态字段。

## 6. 错误与边界处理

- 自动协调失败时保留当前列表，沿用今日任务读取错误和重试入口，不在前端假装状态已经更新。
- 同一任务被用户和计时器同时修改时，数据库条件更新只接受仍为“未开始”的记录，因此人工状态优先。
- 设备时间被向前调整后，下一次协调会按新的当前时间更新到期任务；设备时间回拨不会把“进行中”恢复成“未开始”。
- 没有计划开始时间的情况不在本次范围内；现有模型要求任务具有 `planned_at_ms`。
- 已过计划时间的新建任务在创建后第一次刷新即显示“进行中”，但由于这是创建返回后的首次列表状态，不播放从未在页面出现过的“未开始”过渡。

## 7. 测试与验收

### 后端

- 计划时间未到的“未开始”任务保持不变。
- 计划时间到达或已过的“未开始”任务变为“进行中”。
- 暂停、等别人、已完成、已取消均不被覆盖。
- 重复协调结果幂等，`updated_at_ms`不会在无变化时反复刷新。
- 今日任务查询会补偿应用关闭期间错过的状态变化。
- 人工状态与自动协调并发时，条件更新不覆盖人工结果。

### 前端

- 最近计划时间变化时正确重设一次性计时器并刷新列表。
- 当前会话真实发生“未开始 → 进行中”时显示一次播报。
- 首次加载已进入“进行中”的任务不播放旧播报。
- 播报约四秒收起，也可手动提前收起。
- 状态盖章、自动来源和播报文案在桌面与窄屏均清晰且不遮挡内容。
- 减少动态效果模式下无位移、缩放和旋转动画。
- 任务详情的人工状态操作与终态限制保持正常。

## 8. 非目标

- 不自动完成、取消、暂停或恢复任务。
- 不新增全局通知、声音或系统通知。
- 不重做任务详情状态选择器、历史筛选或数据库状态模型。
- 不修改工作状态、下班倒计时、DDL 提醒和加班逻辑。
- 不为播报文案引入随机服务或可配置文案管理。
