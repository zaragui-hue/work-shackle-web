# 今日任务卡片管理与任务时间规则设计

## 背景

今日待办的新建与编辑抽屉当前使用浏览器原生 `datetime-local` 控件。实际交互中日期入口明显，但时分选择不直观；同时开始时间没有“不得早于当前时刻”的限制。任务详情抽屉还单独包含“任务管理”模块，造成卡片展示状态与抽屉操作状态分离。取消任务虽然会调用取消接口，但主状态的操作路径没有统一表达终态语义。

## 目标

- 未开始任务的开始时间只能选择当前可用分钟及以后，允许跨天。
- 日期与时分使用明确可见、可分别操作的控件。
- 任务开始后锁定开始时间与完成时间，修改完成时间必须走延期流程。
- 将详情抽屉中的任务管理模块迁入今日任务卡片。
- 主状态更新与完成、取消动作使用一致的状态转换语义。
- 移除接头人字段下方的“情报已同步”成功标记。

## 方案选择

采用“卡片内嵌紧凑管理条”。今日任务卡片已有时间进度展示，因此迁移时复用现有进度条，不重复渲染第二条进度；在卡片内容下方增加独立的主状态选择器。卡片主体仍负责打开详情抽屉，状态选择器位于按钮之外，避免交互控件嵌套和点击状态时误开抽屉。

未采用弹出式管理菜单，因为主状态会被隐藏并增加一次操作；也不采用完整展开的管理面板，因为会显著增加每张卡片高度，降低今日任务的扫描效率。

## 日期时间控件

新增共享的日期时间字段组件，将一个毫秒时间拆成两个明确控件：

- 日期：`date` 输入。
- 时分：`time` 输入，精确到分钟。

组件继续向表单提供现有 `yyyy-MM-dd'T'HH:mm` 字符串，避免改变任务 IPC 数据结构。创建抽屉、编辑抽屉和延期弹窗共用该组件。

新建任务打开时，以当前时间向上取整到可选分钟作为默认开始时间。提交时重新以当前分钟校验，开始时间早于当前可用分钟则阻止提交，并在开始时间字段下显示“开始时间不能早于当前时间”。选择当天日期时，时分下限为当前可用分钟；选择未来日期时可选择全天任意时分。

完成时间必须至少晚于开始时间一分钟。延期后的新完成时间必须晚于当前完成时间，并继续满足晚于计划开始时间的后端规则。

## 编辑锁定规则

任务状态为 `not_started` 时，开始时间与完成时间可编辑，并遵守当前时间下限。

任务状态为 `in_progress`、`paused`、`waiting`、`completed` 或 `cancelled` 时，开始时间与完成时间均只读。其他核心字段沿用现有终态只读规则；非终态但已经开始的任务仍可编辑名称、备注、紧急程度和接头人。

已开始任务需要修改完成时间时，必须点击抽屉底部“申请延期”。延期弹窗字段文案从“新 DDL”改为“新完成时间”，明确展示日期、时分和延期原因。

## 卡片任务管理

今日正式任务、历史欠账和已完成任务卡片都使用同一个管理条：

- 非终态任务显示“主状态”选择器。
- 已完成、已取消任务显示只读状态标签，不再提供可编辑选择器。
- 管理条复用卡片已有进度信息；不再在详情抽屉渲染“任务管理”标题、进度条或主状态选择器。
- 点击卡片主体打开详情；点击状态选择器只更新状态，不打开详情。

普通状态 `not_started`、`in_progress`、`paused`、`waiting` 通过 `updateTask` 更新。选择 `completed` 使用 `completeTask`，选择 `cancelled` 先确认再使用 `cancelTask`，确保对应的完成或取消时间戳同步写入。操作失败时恢复原选择并在任务板显示错误；成功后刷新今日任务集合。

抽屉底部的“完成任务”和“取消任务”继续调用同一组专用动作。取消成功后主状态为 `cancelled`，任务从今日进行中列表移除并进入相应历史记录。

## 自动保存反馈

详情抽屉继续字段级自动保存，但不再显示“情报已同步”成功标记，也不在接头人字段后保留占位状态行。保存失败仍显示明确错误，保存期间继续防止完成、取消或延期与保存请求并发。

## 数据与后端校验

前端在创建和编辑未开始任务时校验开始时间下限。后端创建接口增加相同的当前分钟校验，防止绕过界面创建过去开始的任务。

后端编辑接口仅允许修改 `not_started` 任务的计划开始与完成时间。已开始任务即使绕过界面提交时间修改也会返回无效任务输入；延期接口仍是已开始任务修改完成时间的唯一入口。

终态转换继续使用已有 `complete_task` 和 `cancel_task` 命令，不新增数据库字段或迁移。

## 错误与边界

- 用户打开创建抽屉后停留较久，提交时若开始时间已经过去，显示开始时间错误并保留其他输入。
- 选择未来日期后不继承当天的时分下限。
- 将未来日期切回当天时，如果原时分早于当前可用分钟，字段立即进入无效状态，提交被阻止。
- 状态更新期间禁用当前卡片的状态控件，防止重复请求。
- 取消确认被拒绝时恢复原状态，不发送请求。
- 卡片状态请求失败时保留任务和原状态，并提供可重试的错误反馈。

## 验收标准

- 新建任务和未开始任务不能提交早于当前可用分钟的开始时间。
- 日期与时分在新建、编辑和延期界面均有独立可见的选择入口。
- 已开始、暂停、等待、完成和取消任务的时间字段不可编辑。
- 延期弹窗可填写新的完成日期与时分，并要求新完成时间晚于当前完成时间。
- 详情抽屉不再出现“任务管理”模块；今日卡片可直接修改主状态。
- 选择或点击取消任务后，持久化状态和展示状态均为“已取消”。
- 接头人下方不再显示“情报已同步”。
- 相关前端组件测试、表单测试、Rust 服务测试、完整前端测试和生产构建通过。
