# 今日任务紧凑信息带与失控逾期章设计

## 目标

在不牺牲任务状态、DDL 和逾期进度信息的前提下，降低今日正式任务卡片高度，并让历史欠账形成逐级增强的“打工人精神脱轨”视觉冲击。

## 范围

- 调整今日正式任务卡片的信息层级与状态章文案。
- 将剩余时间、计划时间、DDL 和联系人合并为一条紧凑信息带。
- 保留历史欠账的时间进度条，并新增基于超期时长的三级逾期章。
- 不改变任务状态机、自动开工规则、任务排序、数据库字段或后端接口。

## 正式任务卡片

### 信息层级

卡片保持四层紧凑结构：

1. 标题与右上角压力仪表章。
2. 单行时间信息带。
3. 8px 高的任务时间进度条。
4. 自动开工播报条，仅在自动开工发生后的四秒内出现。

倒计时改为信息带中的首项，与计划时间、DDL 和联系人并列：

`还剩 4 小时｜计划 13:30｜DDL 18:00｜产品经理`

信息带在桌面端保持单行。空间不足时允许横向滚动，不让任务标题或状态章被挤压；移动端优先保持倒计时、计划和 DDL 可见，联系人可自然移到下一行。

正式任务原有进度条必须保留，但压缩为信息带下方的独立细轨。填充比例继续表示从计划时间到 DDL 的时间消耗；相同百分比同时作为右上角压力仪表章的主读数。

### 压力仪表章

采用 A「压力仪表章」：右上角只保留一枚约 166×66px 的横向印章。马图以圆形头像压住印章左边缘，时间消耗百分比是最大文字，任务状态吐槽作为底部落款。桌面端不增加独立信息行；移动端缩小为约 142×60px，并随标题自然换到下一行。

印章内部从上到下为：

1. 小号眉题 `TIME USED`；自动开工播报存在时，同一行右侧显示 `AUTO`。
2. 大号百分比，例如 `68%`。
3. 状态吐槽，例如 `🤡 等一个天降奇迹`。

状态吐槽继续按任务状态映射：

| 任务状态 | 展示文案 |
| --- | --- |
| 未开始 | `🫥 活还没醒` |
| 进行中 | `🐴 牛马强制上线` |
| 暂停 | `🫠 工位融化中` |
| 等别人 | `🤡 等一个天降奇迹` |

优先级不再显示“不急 / 正常 / 有点急”文字。任务左侧已有的优先级色轨继续表达优先级；压力仪表章的底色改由时间压力控制，避免一个组件同时表达两套颜色语义。

### 时间压力与马图

百分比为 `(当前时间 - 计划时间) / (DDL - 计划时间)`，开始前显示 `0%`，正常区间四舍五入为整数。逾期后允许超过 100%；读数超过 999% 时显示 `999%+`，避免撑破印章。缺少 DDL 或时间区间无效时显示 `--%` 和中性马图，卡片不显示进度条。

马图、印章颜色和时间情绪使用现有 DDL 分档：

| 时间消耗 | 情绪 | 马图与底色 |
| --- | --- | --- |
| 0%–40% | calm | 职业微笑马，灰米/淡绿 |
| >40%–65% | notice | 职业微笑马，疯黄 |
| >65%–80% | anxious | 断电马，橙黄 |
| >80%–95% | panic | 慌张马，珊瑚红 |
| >95%–100% | burning | 慌张马，危险红 |
| >100% | overdue | 加班石化马，黑红反白 |

压力仪表章的无障碍名称必须同时包含真实任务状态、优先级和时间消耗，例如“任务状态：进行中，紧急程度：正常，时间已走过 68%”。幽默文案和马图不能成为唯一的信息来源。

自动开工时继续沿用现有盖章动画和打工马播报条。减少动画偏好开启时，不使用旋转或缩放动画。

## 历史欠账卡片

### 逾期分档

根据当前时间减去 DDL 的时长分为三档，边界规则如下：

| 超期时长 | 展示文案 | 视觉强度 |
| --- | --- | --- |
| 小于 24 小时 | `有点超时` | 橙红底、轻微倾斜 |
| 24 小时至小于 72 小时 | `严重超时` | 危险红底、更大字号和阴影 |
| 72 小时及以上 | `放弃挣扎` | 黑红反白、最大尺寸、明显盖歪 |

边界以毫秒计算：恰好 24 小时进入“严重超时”，恰好 72 小时进入“放弃挣扎”。

### 卡片结构

历史欠账卡片保留 DDL 时间进度条。进度条继续基于计划时间到 DDL 的区间计算，超过 100% 后保持逾期表现，不截断用于计算的原始比率。

逾期章位于标题右侧，不新增独立信息行。DDL 与精确的“已逾期 N 小时/天”仍保留，便于用户理解分档依据。优先级只保留现有紧凑标签，不与逾期章竞争视觉中心。

## 视觉语言

整体继续使用现有粗边框、纸张底色和硬阴影。新增视觉只把大胆程度集中在状态章和逾期章上，不再增加贴纸、弹幕或背景装饰。

“疯感”来自五个受控变量：短促吐槽、马图越界、百分比放大、印章旋转、分档色彩。正式任务与三级逾期章逐级增强，但标题与时间信息保持规整，保证可扫描性。

## 组件与数据边界

- `TodayTaskCard` 负责选择正式任务或历史欠账的布局。
- 新增纯函数根据任务状态返回吐槽章文案。
- 新增纯函数根据时间比例返回与 Rust DDL 规则一致的情绪分档和百分比文案。
- 新增纯函数根据 `deadlineAtMs` 和当前时间计算逾期等级。
- 正式任务使用一个共享计时状态，同时驱动压力仪表章、信息带倒计时和下方细进度条，避免同一卡片出现不同步读数。
- `DdlTimeProgress` 在历史欠账中继续负责进度条与逾期时间更新，不新增后端请求。
- 正式任务倒计时与历史欠账等级共用现有每秒刷新节奏，跨过 24 小时或 72 小时边界时即时换档。

## 测试与验收

- 单元测试覆盖四种任务状态文案、六档 DDL 情绪边界、百分比上限和无效区间。
- 单元测试覆盖 24 小时和 72 小时边界。
- 组件测试确认正式任务倒计时、计划、DDL 位于同一信息带。
- 组件测试确认正式任务的信息带下方仍存在时间进度条。
- 组件测试确认压力仪表章同时包含马图、百分比、状态吐槽和完整无障碍名称。
- 组件测试确认历史欠账保留进度条和精确逾期时间。
- 组件测试确认无障碍名称仍包含真实状态与优先级。
- 真实页面检查桌面与移动端布局、四秒播报收起、减少动画模式。

## 不做的内容

- 不改变任务的优先级枚举或状态枚举。
- 不新增用户自定义文案或分档阈值设置。
- 不抓取或复制社交平台图片、字体或具体贴纸素材。
- 不修改今日任务分类与自动开工行为。
