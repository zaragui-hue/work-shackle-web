# 今日任务紧凑信息带与失控逾期章设计

## 目标

在不牺牲任务状态、DDL 和逾期进度信息的前提下，降低今日正式任务卡片高度，并让历史欠账形成逐级增强的“打工人精神脱轨”视觉冲击。

## 范围

- 调整今日正式任务卡片的信息层级与状态章文案。
- 将剩余时间、计划时间、DDL 和联系人合并为一条紧凑信息带。
- 保留历史欠账的时间进度条，并新增基于超期时长的三级逾期章。
- 不改变任务状态机、自动开工规则、任务排序、数据库字段或后端接口。

## 正式任务卡片

### 信息层级

卡片保持三层结构：

1. 标题与右上角状态章。
2. 单行时间信息带。
3. 自动开工播报条，仅在自动开工发生后的四秒内出现。

原先独立占行的 DDL 进度条在正式任务中移除。倒计时改为信息带中的首项，与计划时间、DDL 和联系人并列：

`还剩 4 小时｜计划 13:30｜DDL 18:00｜产品经理`

信息带在桌面端保持单行。空间不足时允许横向滚动，不让任务标题或状态章被挤压；移动端优先保持倒计时、计划和 DDL 可见，联系人可自然移到下一行。

### 状态吐槽章

右上角只保留一枚合并章。表情位于文案前，文案按任务状态映射：

| 任务状态 | 展示文案 |
| --- | --- |
| 未开始 | `🫥 活还没醒` |
| 进行中 | `🐴 牛马强制上线` |
| 暂停 | `🫠 工位融化中` |
| 等别人 | `🤡 等一个天降奇迹` |

优先级不再显示“不急 / 正常 / 有点急”文字，而是融入状态章的底色：

| 优先级 | 底色表达 |
| --- | --- |
| 不急 | 灰米色，低对比 |
| 正常 | 疯黄，中等对比 |
| 有点急 | 警报珊瑚红，高对比 |

状态章的无障碍名称必须同时包含真实任务状态和优先级，例如“任务状态：进行中，紧急程度：正常”。幽默文案不能成为唯一的状态信息来源。

自动开工时继续沿用现有盖章动画和打工马播报条。减少动画偏好开启时，不使用旋转或缩放动画。

## 历史欠账卡片

### 逾期分档

根据当前时间减去 DDL 的时长分为三档，边界规则如下：

| 超期时长 | 展示文案 | 视觉强度 |
| --- | --- | --- |
| 小于 24 小时 | `有点超时` | 橙红底、轻微倾斜 |
| 24 小时至小于 72 小时 | `严重超时` | 危险红底、更大字号和阴影 |
| 72 小时及以上 | `放弃挣扎` | 黑红反白、最大尺寸、明显盖歪 |

边界以毫秒计算：恰好 24 小时进入“严重超时”，恰好 72 小时进入“放弃挣扎”。

### 卡片结构

历史欠账卡片保留 DDL 时间进度条。进度条继续基于计划时间到 DDL 的区间计算，超过 100% 后保持逾期表现，不截断用于计算的原始比率。

逾期章位于标题右侧，不新增独立信息行。DDL 与精确的“已逾期 N 小时/天”仍保留，便于用户理解分档依据。优先级只保留现有紧凑标签，不与逾期章竞争视觉中心。

## 视觉语言

整体继续使用现有粗边框、纸张底色和硬阴影。新增视觉只把大胆程度集中在状态章和逾期章上，不再增加贴纸、弹幕或背景装饰。

“疯感”来自四个受控变量：短促吐槽、表情前置、印章旋转、分档色彩。三级逾期章逐级增强，但标题与时间信息保持规整，保证可扫描性。

## 组件与数据边界

- `TodayTaskCard` 负责选择正式任务或历史欠账的布局。
- 新增纯函数根据任务状态返回吐槽章文案。
- 新增纯函数根据优先级返回状态章色调。
- 新增纯函数根据 `deadlineAtMs` 和当前时间计算逾期等级。
- 正式任务的信息带复用现有 DDL 进度数据，只展示倒计时文字，不渲染进度轨道。
- `DdlTimeProgress` 在历史欠账中继续负责进度条与逾期时间更新，不新增后端请求。
- 正式任务倒计时与历史欠账等级共用现有每秒刷新节奏，跨过 24 小时或 72 小时边界时即时换档。

## 测试与验收

- 单元测试覆盖四种任务状态文案与三种优先级色调。
- 单元测试覆盖 24 小时和 72 小时边界。
- 组件测试确认正式任务倒计时、计划、DDL 位于同一信息带。
- 组件测试确认历史欠账保留进度条和精确逾期时间。
- 组件测试确认无障碍名称仍包含真实状态与优先级。
- 真实页面检查桌面与移动端布局、四秒播报收起、减少动画模式。

## 不做的内容

- 不改变任务的优先级枚举或状态枚举。
- 不新增用户自定义文案或分档阈值设置。
- 不抓取或复制社交平台图片、字体或具体贴纸素材。
- 不修改今日任务分类与自动开工行为。
