# DDL 到点爆炸弹窗与进度状态设计

## 目标

任务到达 DDL 时，不再只让卡片悄悄进入逾期状态，而是弹出独立、置顶、可直接处理的“爆炸弹窗”。同时重整任务卡片的时间轨道：放大正常倒计时信息，并把逾期严重程度与超时时长合并为轨道上的唯一状态牌。

本次仅覆盖任务 DDL 到点。午餐、下班和现有工期节点提醒保持现状。

## 整体方案

复用现有 `ddl-reminder` 独立 Tauri 窗口、提醒轮询、窗口置顶、事件传递和任务打开能力，新增系统提醒类型 `ddl_due`。普通提醒继续使用当前“反骨工票”外观；只有 `ddl_due` 切换为“工位事故 / 到点爆炸”外观。

不在主页面添加遮罩弹窗，也不增加系统通知，避免应用最小化后看不到或产生重复提醒。

## 到点事件

### 触发规则

- 任务具有合法的计划时间与 DDL。
- 任务不是 `completed` 或 `cancelled`。
- 当前时间第一次达到或越过 DDL。
- 同一任务、同一个 DDL 快照只触发一次 `ddl_due`。
- 延期后使用新的 DDL 快照重新建立提醒；旧 DDL 的已触发记录不阻止新 DDL。
- 应用启动时间作为到点提醒截止线。启动前已经错过的 DDL 不补弹，避免一打开应用就连续爆炸；应用运行期间因轮询间隔晚到几十秒仍正常触发。

### 与现有节点的关系

现有 `progress_half`、`quarter_remaining` 和 `one_hour_remaining` 保持不变。到达 DDL 后只处理 `ddl_due`，不补发此前遗漏的低优先级节点。

同一次轮询有多个任务到点时，沿用现有合并机制：选择一个任务作为主弹窗，并显示“还有 N 个任务也炸了”。`ddl_due` 优先级高于自定义提醒和其他系统节点。

## 爆炸弹窗

### 视觉

窗口沿用 520px 宽的固定置顶窗口，`ddl_due` 模式固定为 520×560px，以容纳延期编辑器。视觉采用克制的事故票据：

- 奶油纸张底色与黑色硬边框承载正文。
- 一块大面积事故红作为唯一爆炸区，显示“到点爆炸”和爆炸图形。
- 黄色用于原 DDL 和延期时间输入。
- 蓝色只用于确认延期等正向操作。
- 不叠加连续倾斜、霓虹、粒子或大面积动画。
- 仅允许事故印章在出现时做一次 600ms 抖动；`prefers-reduced-motion` 下关闭。

弹窗文案：

- 眉题：`DDL 已归零 · 现在不是演习`
- 主标题：任务名称
- 正文：`这活正式炸了。现在处理还能叫抢救，再拖就只能叫考古。`
- 时间：`原定完成时间 18:00`
- 多任务：`还有 N 个任务也炸了`

### 操作

弹窗提供三个一级操作：

1. `现在处理`
   - `not_started`、`paused`、`waiting` 切换为 `in_progress`。
   - 已经是 `in_progress` 时不重复保存。
   - 显示并聚焦主窗口，打开对应任务抽屉，然后关闭提醒窗口。

2. `延期`
   - 在弹窗原位展开时间选择器，不跳转主窗口。
   - 使用与“下班时间”一致的原生 `input type="time"` 交互与视觉。
   - 默认时间为当前时间后一小时，按分钟显示。
   - 选择的时刻若晚于当前时刻，解释为今天；若早于或等于当前时刻，解释为明天。
   - 确认后调用现有延期能力，延期原因为 `到点爆炸弹窗延期`，成功后关闭窗口。

3. `结束任务`
   - 调用现有完成任务能力，语义为完成而非取消。
   - 成功后关闭窗口，并刷新主页面任务集合。

窗口右上角关闭或系统关闭等价于“暂不处理”：只隐藏本次弹窗，不修改任务。因为 `ddl_due` 已记录触发，同一 DDL 不再反复弹出。

### 失败处理

- 状态切换、延期或完成失败时，弹窗保持打开。
- 在操作区上方显示映射后的具体错误，按钮恢复可用。
- 不进行乐观关闭，不静默吞错。
- 主窗口或任务抽屉无法打开时，显示错误并保留弹窗。

## 任务卡片时间轨道

### 正常任务

“距离爆炸”状态牌保持跟随时间进度节点，但提升可读性：

- 标签与时间数字整体放大。
- 使用黑色底、浅色字和单一蓝色偏移阴影，不再混入红、蓝、黄三种竞争色。
- 标记靠近轨道两端时继续自动收边。
- 桌面显示两行 `距离爆炸 / 还剩 3 小时`；窄屏隐藏标签但保留放大的时间数字。

### 逾期任务

移除卡片右上角独立的 `有点超时`、`严重超时`、`放弃挣扎` 标签。逾期严重程度与时长只在红色满格轨道上显示一次：

- 24 小时内：`尸体还热，赶紧抢救 / 超时 12 小时`
- 24–72 小时：`已经烂透，优先处理 / 超时 2 天`
- 72 小时以上：`永久工位，爱咋咋地 / 超时 4 天`

状态牌固定在轨道右端。无障碍名称组合为完整句，例如 `尸体还热，赶紧抢救，超时 12 小时`。原 DDL 继续显示在轨道下方，逾期轨道的 `aria-valuenow` 保持 100。

## 数据与组件边界

- `SystemReminderKind`：新增 `DdlDue`，负责字符串映射、紧急度与持久化去重。
- 系统节点计算：产生位于 DDL 本身的 `ddl_due` 节点；原有节点仍要求处于计划区间内部。
- 提醒引擎：区分运行期到点与启动前旧 DDL，只触发合格的 `ddl_due`。
- `ReminderWindowView`：按提醒类型分派普通票据或爆炸票据。
- 爆炸票据组件：只负责展示、展开延期输入和触发操作回调，不直接包含 Tauri 窗口逻辑。
- 提醒窗口操作服务：封装状态切换、完成、延期、打开主窗口和通知主页面刷新。
- 轨道显示辅助函数：根据逾期毫秒数返回稳定的疯感状态文案，供组件和测试共用。

## 测试与验收

### Rust

- 节点计算包含 `ddl_due`，触发时间等于 DDL。
- 到点提醒在运行期间只触发一次。
- 应用启动前已过期的任务不补触发。
- 延期后的新 DDL 可以再次触发。
- 完成与取消任务不进入候选集合。
- 多提醒排序中 `ddl_due` 优先。

### React

- `ddl_due` 渲染爆炸票据，其他提醒外观不变。
- 三个操作触发正确服务；失败时保留窗口并显示错误。
- 延期输入按“今天晚些时候 / 否则明天”生成时间戳。
- 卡片不再渲染独立逾期标签。
- 三档逾期状态文案、满格轨道、无障碍名称正确。
- 正常轨道状态牌字号与移动端收缩规则正确。

### 视觉

- 独立窗口在 520×560 内无溢出，长任务名称可换行。
- 延期编辑器展开后按钮和错误信息仍可见。
- 今日页面桌面宽度与 390px 宽度无横向溢出。
- 正常倒计时能一眼读清，逾期卡片没有重复严重程度。
- 所有按钮有可见键盘焦点，减少动态效果设置生效。
