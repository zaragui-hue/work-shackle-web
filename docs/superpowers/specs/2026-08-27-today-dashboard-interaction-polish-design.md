# 今日页交互打磨设计

## 目标

对今日页的工位控制台、下班倒计时、任务区标题、任务卡片操作和右侧抽屉进行一轮聚焦打磨，使时间选择交互一致、文案随工作进程变化，并让延期、默认时间校准与只读状态更直观。

本次只调整现有交互与视觉，不改变任务主状态模型、数据库结构或 Tauri IPC 数据格式。

## 方案选择

采用复用现有能力的定点增强方案：控制台沿用项目已经确认的小时/分钟选择交互；延期继续调用现有延期弹窗与后端能力；动态文案和时间校准由小型纯函数承担。相比抽取覆盖所有场景的全局时间组件，这一方案边界清晰、回归风险较低，也避免为了控制台的单一时分场景过度抽象。

## 工位控制台时间选择器

控制台现有的大号原生 `input type="time"` 改为小时与分钟两个下拉选择器：

- 小时提供 `00`–`23`；
- 分钟提供 `00`–`59`，精确到 1 分钟；
- 两个选择器保持现有大号计分牌视觉，中间显示冒号；
- 用户修改任一选择后立即保存，不增加确认按钮；
- 保存进行中时禁用两个选择器；
- 保存失败时小时与分钟一起恢复为当前生效的下班时间，并显示现有错误提示；
- 后端继续接收 `HH:mm` 字符串，设置页与提醒时间控件不在本次范围内。

## 下班倒计时动态文案

工作阶段的主标题不再始终显示“距离下班还有”，而是按当天工作进度稳定切换：

| 工作进度 | 主标题 |
|---|---|
| 0%–24% | 离下班还早，先把今天骗过去 |
| 25%–49% | 工位坐稳，释放正在路上 |
| 50%–74% | 已经熬过一半，别在这时散架 |
| 75%–89% | 下班开始有轮廓了 |
| 90%–100% | 再撑一下，门禁快拦不住你了 |

文案由工作进度确定，不使用随机数，因此同一进度区间在刷新和重渲染时保持稳定。开工前与到达下班时间后的现有文案继续保留。倒计时数字、工作进度计算与打工马动画不改变。

## 今日任务区标题

“今天这些破事 / 先狠狠干掉”改为与“昨日烂尾现场”一致的区块标题结构：

- 使用同一标题字号、字重、行高和字间距；
- 标题行下方使用相同的墨色粗分隔线；
- 右侧使用同规格的小型徽章，显示“今日清单”；
- 保留现有任务区外框、工具栏和任务列表，不改变任务信息层级。

## 任务卡片延期入口

非终态任务卡片的主状态下拉末尾增加“申请延期”操作项。它只是界面操作，不加入 `TaskStatus`，也不写入任务主状态：

1. 用户选择“申请延期”；
2. 下拉框继续显示任务原有主状态；
3. 页面打开现有 `PostponeTaskModal`；
4. 用户填写新的完成时间和延期原因；
5. 延期成功后刷新今日任务列表，主状态保持原值，延期历史正常追加；
6. 用户取消或延期失败时，卡片原状态不变。

已完成和已取消任务继续显示只读状态标签，不提供延期入口。没有完成时间的任务不提供延期入口。

## 新建任务默认开始时间自动校准

新建任务右侧抽屉打开时，开始时间继续默认使用当前可用分钟。抽屉记录用户是否主动修改过开始时间：

- 若用户未修改开始时间，提交时重新读取当前可用分钟；默认开始时间已经落后时，自动校准到新的当前分钟；
- 例如 18:17 打开抽屉、18:18 提交，开始时间自动保存为 18:18；
- 若校准后的开始时间不再早于完成时间，完成时间同步调整为开始时间后 1 分钟，以保持合法时间区间；
- 若用户主动修改过开始时间，提交时不自动覆盖用户选择，继续执行现有表单校验；
- 该行为只用于新建任务，不用于编辑已有任务。

“用户主动修改”包括修改开始日期、小时或分钟中的任意一项。

## 不可编辑字段的视觉

共享任务核心字段为禁用状态时应明确置灰，同时保持内容可读和无障碍语义：

- 禁用输入框、文本域、日期输入和下拉框使用灰底、灰色边框与较低对比度文字；
- 已开始任务的整个“任务时间段”区域降低饱和度，开始与完成时间都呈现为只读；
- 终态任务的全部核心字段呈现统一的禁用视觉；
- 禁用控件保留原生 `disabled` 语义，不用纯视觉遮罩代替；
- “任务已开始，完成时间请通过申请延期调整”和“此任务已结束，详情为只读”继续说明不可编辑原因。

## 组件边界与数据流

- `WorkScheduleEditor` 负责控制台小时/分钟选择和即时保存；时分拆分、合并使用独立纯函数。
- `workCountdown` 负责按进度选择稳定文案，`WorkCountdownBanner` 只负责呈现。
- `TodayTaskCard` 暴露延期请求回调；`TodayTaskBoard` 与 `TodayPage` 逐层传递请求并管理现有延期弹窗。
- `CreateTaskDrawer` 负责追踪开始时间是否被用户修改，并在提交前校准未修改的默认值。
- `TaskCoreFields` 与现有共享输入样式负责统一禁用视觉。

延期弹窗仍是延期时间、原因和后端调用的唯一所有者，卡片不复制延期表单。

## 错误处理

- 控制台时间保存失败时回滚到当前生效值并显示错误；
- 延期失败时弹窗保持打开，卡片状态不变；
- 创建任务校准后仍必须通过现有表单和后端校验；
- 所有已有错误提示继续保留，不以静默失败代替。

## 测试与验收

自动化测试覆盖：

- 控制台渲染小时/分钟选择器、修改即保存以及失败回滚；
- 动态文案在 0%、25%、50%、75%、90% 和 100% 边界的结果；
- 今日标题与昨日标题共享标题行样式结构；
- 卡片选择“申请延期”会打开弹窗且不会修改主状态；
- 延期取消、失败和成功刷新；
- 新建抽屉未修改默认时间时的跨分钟校准；
- 用户主动修改开始时间后不被自动覆盖；
- 校准导致时间区间冲突时完成时间自动推后 1 分钟；
- 已开始与终态任务的禁用控件和置灰样式钩子。

完成后运行相关组件测试、完整前端测试和生产构建，并重启 Tauri 桌面应用进行人工检查。
