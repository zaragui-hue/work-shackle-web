# Web 今日页 App UI 对齐设计

## 目标

将独立 Web 端的「今日」页面视觉与当前桌面 App 保持一致，同时保留 Web 已实现的浏览器文件夹存储和今日页业务能力。Web 与 App 继续分别维护；本次只复制当前已确认的 App 呈现，不建立双端自动同步。

## 实施方案

采用 Web 内独立复刻方案：参考 App 当前组件结构、视觉令牌和交互表现，在 `web/` 内建立对应的呈现组件并连接 Web 现有数据模型。不得抽取 App 与 Web 共享组件，也不得修改 App 的 `src/`、`src-tauri/` 或桌面打包配置。

相比只替换 CSS，该方案能准确复刻页面层级和交互；相比共用组件，该方案不会使未来 App 更新自动影响 Web。

## 页面外壳与导航

- Web 使用与 App 相同的纸张背景、黄色品牌栏、圆形 `WS` 标识、品牌文案、实时工作状态和三段导航。
- 保留「今日」「任务」「设置」三个入口，「今日」保持选中。
- 点击「任务」或「设置」时不离开今日页，以非阻断轻量提示说明对应 Web 页面暂未开放。
- 导航提示可关闭，并具备可读的状态语义；重复点击只更新同一提示，不堆叠多个提示。
- Web 独有的保存状态不放在品牌栏，避免改变 App 顶部结构。

## 今日页布局与视觉

- 首屏复刻 App 的黑色下班倒计时舞台，包括动态阶段文案、主倒计时、工作进度、打工马轨道和事件状态反馈。
- 页面下半区使用 App 的两列布局：左侧为今日任务，右侧为工位时间与提醒；窄桌面窗口时按 App 的响应式规则变为单列。
- 复用 App 当前视觉语言：纸张灰背景、抬升纸白卡片、墨黑舞台、电光蓝信息、荧光绿完成/下班、警报红异常，以及对应的边框、圆角、字重和数据字体。
- 使用 App 已有的本地打工马素材，不使用 emoji 作为正式页面角色；素材复制到 Web 自己的资源目录，保持双端独立。
- 加载、空状态、错误、状态提示与保存反馈使用同一套视觉组件语言。

## 今日任务与表单

- 任务区域复刻 App 的区块标题、票据式任务卡、时间信息、优先级、DDL 进度、状态选择和操作层级。
- 保留今日正式任务、即将到期、逾期和已完成分组；没有任务时显示与 App 一致的空状态层级。
- 「新任务」放在 App 今日任务区对应位置，继续保留 Web 已有新建能力。
- 新建与编辑使用右侧抽屉，并复刻 App 当前字段结构、禁用状态和操作区视觉。
- 延期继续使用独立弹窗，保持现有 Web 延期规则和历史记录写入。
- 完成、取消、延期和优先级调整只连接 Web 业务函数，不调用 Tauri 服务。

## 工位控制与 Web 专属信息

- 右侧区域复刻 App 的工位时间、状态切换、提醒和辅助说明呈现。
- Web 现有上下班时间、午休、加班、工作提醒和页面打开期间的定时检查完整保留。
- Web 独有的「已保存 / 正在保存 / 尚未保存」状态放在右侧工位卡片底部；保存失败时显示明确原因和恢复提示。
- 本地文件夹选择、重新授权、数据恢复等启动页面使用相同视觉令牌，但保留 Web 专属文案和流程。
- 浏览器通知仍需用户授权；页面或浏览器关闭后不承诺继续触发系统提醒。

## 数据和兼容性

- 不改变现有 `work-shackle-web.json` 数据结构、文件名、备份规则或文件夹句柄存储方式。
- 升级后的 Web 必须直接读取当前历史数据，不执行清空、重置或不兼容迁移。
- 所有修改继续通过 Web 现有业务函数更新内存状态，再由现有串行保存流程写入用户选择的文件夹。
- 权限失效时要求用户重新授权原文件夹；保存失败时不得用空数据覆盖主文件。
- App 的 SQLite 数据与 Web 文件数据保持隔离，不新增自动导入或同步。

## 组件边界

- Web 应用外壳负责品牌、实时状态、导航和未开放提示。
- 倒计时舞台负责工作阶段、时间、进度和打工马呈现，只接收 Web 已计算的显示数据。
- 今日任务板负责分组和任务操作回调；任务卡只负责单条任务呈现。
- 工位控制区负责班表、状态、提醒以及保存状态展示。
- 抽屉和弹窗负责表单交互，业务校验继续留在 Web 领域函数或表单提交边界。
- 文件数据层保持独立，不依赖任何 App 组件或 Tauri API。

## 错误处理

- 不支持 File System Access API 时继续阻止进入业务页并提示使用最新版 Chrome 或 Edge。
- 文件权限失效、数据损坏和恢复失败继续进入 Web 专属恢复流程，但统一为 App 风格。
- 保存失败时保留内存中的当前修改，显示「尚未保存」和明确错误，不伪装成成功。
- 任务输入错误在抽屉或弹窗内就地显示；取消任务继续要求确认。
- 未开放导航只显示提示，不改变当前表单、任务数据或保存状态。

## 测试与验收

自动化测试覆盖：

- 三段导航存在，「今日」激活，点击「任务」或「设置」显示未开放提示且不切换页面；
- 原有任务新建、编辑、完成、取消、延期和优先级行为保持通过；
- 保存状态在右侧区域显示，保存失败反馈保持可见；
- 现有数据模型和本地文件读写测试全部通过；
- 倒计时、工作状态、午休、加班和提醒计算不因 UI 重构而变化。

人工验收覆盖：

- 与当前 App 今日页对照品牌栏、导航、倒计时舞台、任务区、右侧工位区、抽屉和弹窗；
- 在常见电脑浏览器宽度和窄桌面宽度下检查布局；
- 使用已有数据文件夹打开、刷新和重新授权，确认历史数据保留；
- 新建并修改任务后重新打开页面，确认数据仍在；
- GitHub Pages 生产构建可正常加载资源和使用文件夹授权。

## 发布

完成测试和生产构建后，只将 `web/` 子项目更新推送到独立的 `work-shackle-web` GitHub 仓库，由现有 GitHub Pages 工作流重新发布。App 仓库中的桌面代码不随 Web 发布内容上传。

## 不在本次范围

- Web 任务页和设置页的实际功能；
- App 端任何代码或视觉调整；
- App 与 Web 的组件共享、数据同步或自动跟随更新；
- 手机端专项设计；
- 浏览器关闭后的后台常驻提醒；
- 服务端、账号、云数据库或多端实时同步。
