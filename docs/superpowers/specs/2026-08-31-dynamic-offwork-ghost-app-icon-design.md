# Work Shackle「下班小鬼」动态图标设计

> 状态：视觉与行为方向已确认，待书面复核
> 日期：2026-08-31
> 范围：应用主图标、运行时图标状态解析、桌面系统图标更新与测试

## 1. 目标

用一套简单、可爱、潮流的原创角色图标替换当前通用抽象图标，并让图标像一个陪伴用户度过工作日的表情角色：普通时段随时间逐渐“掉电”，临近下班时恢复精神，DDL 或加班发生时立即切换为更强烈的状态。

成功标准：

1. 缩小到 32px 时仍能认出角色、眼神和主色，不依赖文字或细碎道具。
2. 静态主图标本身成立，不了解动态机制的用户也能感受到产品的幽默性格。
3. 六种状态保持同一角色轮廓，只改变背景色、眼睛、嘴和极少量符号。
4. 状态切换与真实时间、DDL 和加班事实一致，不随机发疯。
5. 动态替换失败不影响业务功能，也不弹窗打扰用户。

一句话原则：**时间负责陪伴感，DDL 负责提醒感，下班负责奖励感。**

## 2. 已确认方向

- 不再要求延续“打工马”；新角色是原创的「下班小鬼」。
- 视觉性格采用「欠欠的乐子人」：挑眉、坏笑、带一点反骨，但不凶、不恐怖。
- 造型采用白色圆润幽灵轮廓，底部三段软尖角，深色粗描边。
- 主配色采用紫色背景、近白角色、墨黑五官，荧光绿与珊瑚红只在关键状态出现。
- 图标由时间与工作状态共同驱动；关键工作状态覆盖普通时间状态。
- 安装包、应用商店和不支持运行时替换的系统入口使用永久主图标。

## 3. 核心视觉

### 3.1 角色轮廓

「下班小鬼」占图标画布约 68%–72%，头顶为完整圆弧，身体两侧垂直向下，底部用三段大波浪表达幽灵轮廓。角色始终正面出现，不使用手脚、衣服、文字或复杂办公道具。

固定特征：

- 近白色主体；
- 墨黑粗描边；
- 两只大眼和一张高对比嘴；
- 右上角一个小圆形时钟；
- 轻微不对称的眉毛，形成“欠欠的”品牌表情。

六种状态必须复用同一主体尺寸、位置、描边宽度和时钟位置，避免切换时产生角色跳动。

### 3.2 色彩

| 角色 | 色值 | 用途 |
|---|---|---|
| 品牌紫 | `#7557FF` | 永久主图标、正常工作状态 |
| 清晨紫 | `#9B83FF` | 早晨状态 |
| 午后灰紫 | `#6C5A86` | 午后低能量状态 |
| 荧光绿 | `#C7FF5A` | 临近下班的奖励状态 |
| 珊瑚红 | `#FF5E71` | DDL 紧急和逾期状态 |
| 深夜黑蓝 | `#171827` | 深夜加班状态 |
| 小鬼白 | `#FBFAFF` | 正常角色主体 |
| 五官黑 | `#17152A` | 轮廓与五官 |
| 嘴部粉 | `#FF6D9E` | 默认坏笑嘴、局部活力点 |

颜色使用纯色或极轻微的明度变化，不使用玻璃质感、复杂渐变、3D 材质和写实阴影。

### 3.3 永久主图标

永久主图标使用「上午 · 乐子人营业」状态：品牌紫背景、白色小鬼、左右高低不同的眉毛、黑色椭圆眼睛和粉色坏笑嘴。它用于：

- Tauri bundle 的 `.icns`、`.ico` 和各尺寸 PNG；
- macOS Finder、Windows 开始菜单、安装包和应用商店素材；
- Web favicon；
- 运行时动态替换不可用或失败时的回退。

## 4. 六种图标状态

| 状态键 | 视觉 | 普通触发条件 |
|---|---|---|
| `morning` | 清晨紫、眨眼、轻松笑 | 本地时间早于 10:00 |
| `default` | 品牌紫、挑眉、坏笑 | 10:00 至 13:59 |
| `afternoon` | 灰紫、半闭眼、平嘴 | 14:00 后，且未进入更高优先级状态 |
| `offwork_soon` | 荧光绿、笑眼、大笑 | 距配置的下班时间 30 分钟以内且尚未下班 |
| `deadline_alert` | 珊瑚红、大白眼、张嘴、冷汗 | 存在 30 分钟内到期或已逾期的未完成任务 |
| `overtime` | 深夜黑蓝、灰色主体、叉眼、下垂嘴 | 已进入加班状态，或下班时间后仍明确处于工作中 |

永久主图标与 `default` 共用同一份视觉母版。

### 4.1 状态优先级

解析器按以下顺序命中第一个状态：

```text
deadline_alert > overtime > offwork_soon > morning/default/afternoon
```

补充规则：

- 已完成、已暂停或已删除的任务不触发 `deadline_alert`。
- 多个紧急任务同时存在时仍只显示一个 `deadline_alert` 图标，不叠加数字或文字。
- 任务延期后，旧 DDL 立即失效，由新 DDL 重新参与判断。
- 下班时间不存在或当天班表不可用时，不显示 `offwork_soon` 或基于班表推断的 `overtime`；仍可依据显式加班状态显示 `overtime`。
- 周末或非工作日没有特殊图标，继续使用普通时间状态；本轮不新增节假日图标。
- 完成单个任务不产生短暂动态图标，避免 Dock 图标频繁闪动；奖励感集中在 `offwork_soon`。

## 5. 状态解析与数据流

新增一个纯函数状态解析器，输入只包含判断所需事实：

```text
当前本地时间
+ 当天下班时间（可为空）
+ 是否处于显式加班状态
+ 是否仍明确处于工作状态
+ 未完成任务的最近 DDL（可为空）
→ DynamicAppIconState
```

数据流：

```text
现有任务 / 班表 / 加班数据
        ↓
动态图标快照组装器
        ↓
纯状态解析器 resolveDynamicAppIconState
        ↓
状态键 → 本地图标素材表
        ↓
桌面图标控制器（仅在状态变化时调用系统能力）
```

解析器不读取系统 API、不加载图片、不保存状态。它只返回六个状态键之一，因此时间边界和优先级可以独立单元测试。

## 6. 更新时机

动态图标控制器在以下时机重新计算：

1. App 完成初始化并进入主界面；
2. 每个本地整分钟；
3. 任务创建、完成、暂停、延期或删除后；
4. 工作状态、班表或加班状态改变后；
5. App 从后台恢复或窗口重新获得焦点时。

控制器缓存最后一次成功应用的状态键。计算结果与缓存相同时不重复加载图片，也不调用系统图标接口。

不使用秒级轮询。整分钟刷新足以覆盖 10:00、14:00、下班前 30 分钟和 DDL 30 分钟边界，同时避免无意义的高频调用。

## 7. 组件与文件边界

建议按职责拆分：

- `dynamicAppIconState.ts`：状态枚举、输入类型、纯解析器与时间边界逻辑。
- `dynamicAppIconAssets.ts`：六个状态键到本地 PNG 的完整映射。
- `dynamicAppIconSnapshot.ts`：从现有任务、班表和工作状态组装解析器输入。
- `useDynamicAppIcon.ts`：订阅业务变化、整分钟计时、窗口恢复和去重。
- `appIconController.ts`：封装 Tauri 窗口图标能力以及失败降级。
- `src/assets/app-icons/offwork-ghost/`：SVG 母版与运行时 PNG 素材。

页面组件不得直接判断图标状态，也不得直接调用 `setIcon`。现有任务、提醒和工作状态逻辑继续作为事实来源，不为动态图标复制第二套业务规则。

## 8. 平台行为与降级

项目当前使用的 Tauri API 提供运行时窗口图标替换能力。首版行为如下：

- macOS：优先更新运行中 App 的 Dock / 窗口图标。
- Windows：更新运行时窗口图标；任务栏是否即时刷新由系统行为决定。
- Linux：尽力更新窗口图标，实际呈现取决于桌面环境。
- Web 构建：使用永久主图标，不运行桌面图标控制器。
- Finder、开始菜单、安装包和应用商店图标保持永久主图标，不承诺运行时变化。

运行时图标替换失败时：

1. 记录开发环境可诊断的错误；
2. 保留最后一次成功图标；
3. 若从未成功，则继续使用 bundle 主图标；
4. 不显示 Toast、模态框或系统通知；
5. 不影响任务、提醒、班表和加班功能。

## 9. 素材生产规范

每个状态先制作一个共享结构的 SVG 母版，再由确定性脚本导出 PNG。禁止分别手绘六张互不关联的位图，以免轮廓和位置漂移。

交付规格：

- 六张 1024×1024 PNG 运行时素材；
- 永久主图标生成 32×32、128×128、256×256、512×512 和 1024×1024 PNG；
- 由永久主图标生成 macOS `.icns` 与 Windows `.ico`；
- Web favicon 使用永久主图标；
- 所有素材打包进应用，不依赖网络。

安全区：角色、时钟和表情必须位于画布四周 12% 内缩范围内。32px 验收时允许弱化眉毛和时钟指针，但眼睛、嘴型和背景色必须清晰。

## 10. 测试

### 10.1 状态解析器

至少覆盖：

- 09:59、10:00、13:59、14:00 的基础状态边界；
- 下班前 31 分钟与 30 分钟；
- DDL 前 31 分钟、30 分钟、到点与逾期；
- 已完成、暂停、延期任务不错误触发旧状态；
- DDL、加班、临近下班同时成立时的优先级；
- 无班表、非工作日和本地跨日边界。

### 10.2 控制器与 Hook

- 初始化时应用一次正确图标；
- 同一状态不重复调用系统接口；
- 业务数据改变和整分钟事件会重新解析；
- 窗口恢复时补算后台期间跨过的状态边界；
- Tauri 调用失败后不抛到页面、不阻断后续重试；
- Web 环境不调用桌面 API。

### 10.3 素材契约

- 六个状态都有对应文件；
- PNG 尺寸与透明/不透明要求正确；
- bundle 配置引用的新主图标文件存在；
- 默认状态与永久主图标视觉一致；
- 32px、128px、256px 和 1024px 人工检查无裁切、无模糊边缘。

### 10.4 回归验证

- TypeScript 构建通过；
- Vitest 全量测试通过；
- Tauri 配置校验与桌面开发构建通过；
- macOS 实机验证 Dock 图标切换、窗口重聚焦和 App 重启回退；
- Windows 安装包构建可用时验证 bundle 图标与运行时窗口图标。

## 11. 实施范围

本轮包含：

- 「下班小鬼」永久主图标与六种状态素材；
- bundle、Web favicon 和运行时素材替换；
- 状态解析、数据快照、整分钟更新、事件更新与失败降级；
- 单元测试、素材契约测试、构建和桌面验证。

本轮不包含：

- 节假日、生日、连续打卡等节庆图标；
- 用户自定义图标或关闭单个状态；
- 系统托盘菜单和托盘专用图标；
- Dock 数字角标、任务数量角标或未读红点；
- 图标动画、视频图标或秒级变化；
- 社交分享、贴纸包和角色周边素材。
