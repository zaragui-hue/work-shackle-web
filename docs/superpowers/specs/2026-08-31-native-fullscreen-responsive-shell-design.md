# 原生全屏自适应外壳设计

## 背景

应用普通窗口外壳固定为最大 `1260px` 并带有外边距、圆角和硬阴影。用户通过 macOS/Tauri 窗口按钮进入全屏后，视口变宽，但外壳仍保持普通窗口尺寸，导致两侧出现大面积空白，也缺少应用内可发现的退出全屏入口。

## 目标

- 原生全屏时 UI 铺满整个可用视口，不保留普通窗口的外边距或最大宽度限制。
- 在顶部栏提供明确、可键盘操作的“退出全屏”按钮。
- 通过系统窗口按钮进入或退出全屏时，应用状态与布局自动同步。
- 普通窗口、窄窗口和手机断点保持现有布局行为。
- 不覆盖当前工作区中尚未提交的粘性顶部栏改动。

## 已确认方案

使用 Tauri 原生窗口 API 作为唯一全屏状态来源：首次渲染读取 `isFullscreen()`，监听窗口尺寸变化后重新读取状态，并通过 `setFullscreen(false)` 退出。网页宽度不作为全屏状态判断依据。

## 组件与状态

新增 `useWindowFullscreen` hook：

- 暴露 `isFullscreen`、`exiting` 与 `exitFullscreen()`。
- 浏览器预览或 Tauri API 不可用时安全回落为非全屏，不影响开发预览。
- 组件卸载时移除窗口尺寸监听。
- 退出操作进行时防止重复触发；失败后恢复按钮可用状态。

`AppShell` 根据 hook 状态：

- 在根节点添加 `ws-shell--fullscreen` 修饰类。
- 仅在真实全屏时，于顶部右侧、状态徽章与主导航之前显示“退出全屏”按钮。
- 按钮使用原生 `button`、清晰文本和收拢箭头图标，避免只依赖图形表达。

## 布局与视觉

新增独立的 `AppShellFullscreen.css`，在现有 `AppShell.css` 之后加载，避免改写尚未提交的普通窗口样式。

全屏状态：

- 外壳宽度和最小高度为整个视口，最大宽度不限。
- `margin: 0`，移除外层圆角、外边框和外部阴影。
- 使用响应式内边距 `clamp(12px, 1.4vw, 28px)`，使 1080p、2K 与超宽屏保持合理密度。
- 今日页右侧工位控制台使用 `clamp(340px, 22vw, 460px)`，左侧任务区占据剩余空间。
- 顶部栏继续使用现有粘性定位；退出按钮采用墨黑底、黄色文字、红色硬阴影，与当前工牌式界面一致。

普通窗口不应用上述修饰规则，继续保留居中卡片外框。

## 权限与错误处理

- 在主窗口能力配置中加入 `core:window:allow-set-fullscreen`。
- `core:default` 已包含读取全屏状态所需的 `allow-is-fullscreen`。
- 若状态读取失败，界面按普通窗口呈现，不显示无效退出按钮。
- 若退出失败，按钮重新可用；不伪造已退出状态，等待下一次原生窗口事件同步。

## 可访问性与响应式

- 按钮可通过 Tab 聚焦，名称固定为“退出全屏”。
- `exiting` 时禁用按钮并显示“正在退出”，避免重复提交。
- 收拢箭头标记为装饰，不替代按钮文字。
- 900px 以下顶部栏可换行；720px 以下沿用现有单列顶部栏和页面布局。
- 本次不新增动画，现有减少动态效果设置保持有效。

## 测试与验收

1. hook 测试覆盖初始全屏、系统退出后的状态同步、按钮退出和 API 失败回落。
2. AppShell 结构测试验证全屏修饰类、条件按钮及无障碍名称。
3. CSS 契约测试验证全屏外壳无最大宽度、零外边距、零圆角以及今日页弹性右栏。
4. 能力配置测试或源码断言验证 `allow-set-fullscreen` 已启用。
5. 全量 Vitest 与生产构建通过。
6. 在桌面宽屏视口模拟全屏类，确认界面铺满且无水平滚动；在普通窗口确认外框样式未改变。

## 非目标

- 不新增“进入全屏”按钮；用户继续使用系统窗口入口。
- 不把普通的最大化窗口视为全屏。
- 不修改任务、倒计时、排班或工作状态业务逻辑。
- 不修改当前未提交的 `AppShell.css` 粘性顶部栏改动。
