# 工位小闹钟舒适卡片与显式保存设计

## 目标

将工位小闹钟调整为更轻、更易扫读的紧凑日程卡。删除冗余标题和开启状态，恢复单卡“保存”动作，增加安全的一键清空，并让已保存配置持续跨天沿用。

## 已确认交互

- 区域只显示“工位小闹钟”，删除“上班过程提醒”。
- 顶部右侧显示“清空全部”和“＋ 添加”。
- 已保存卡片只显示时间段、内容和“编辑 ›”，不显示“已开启、已关闭、待设置”等状态，不提供启用开关。
- 点击添加后展开一张新卡片草稿；点击编辑后以已保存值创建编辑草稿。
- 草稿包含开始时间、结束时间、内容、取消和保存；编辑已有记录时额外显示单条删除。
- 草稿修改不会立即写入已保存列表。点击保存并通过校验后才正式生效。
- 点击取消放弃本次修改，恢复已保存内容；新增草稿取消后直接消失。
- 编辑期间禁止打开其他卡片，也禁止添加或清空，并提示“请先保存或取消当前修改”。
- 保存成功后卡片折叠，并按开始时间升序重排。

## 清空全部

- 第一次点击“清空全部”后，原按钮区域变为“确认清空”和“取消”。
- 只有点击“确认清空”才删除全部已保存小闹钟。
- 列表为空时禁用清空按钮。
- 有未保存草稿时不能进入清空确认。

## 数据与长期沿用

- 已保存的小闹钟是全局日程模板，不按工作日期保存，因此今天、明天和后天都会继续使用。
- 配置持续保存在本地，直到用户单条删除或确认清空全部。
- 草稿只存在于当前界面状态，不写入持久化存储。
- 数据模型升级为无启用状态的 v3：

```ts
type WorkdayReminder = {
  id: string;
  startTime: string;
  endTime: string;
  statusType: string;
  createdAtMs: number;
};
```

- v2 迁移时只保留已启用、内容有效且时间合法的记录；旧的未启用草稿不迁移。
- v3 存储存在空数组时表示用户主动清空，不再恢复默认记录。

## 校验与错误

- 保存时校验内容、开始早于结束、位于排班范围内以及不与其他记录重叠。
- 校验失败时保留草稿并在卡片内显示错误；已保存数据不变。
- 持久化失败时保留编辑状态并显示“保存失败，请重试”。
- 删除或清空持久化失败时保留原列表，不关闭当前编辑状态。

## 视觉方案

采用已选定的 A“紧凑日程卡”：

- 顶部使用一个明确标题和两个低高度操作按钮。
- 折叠行通过时间、内容和编辑入口形成单行层级。
- 仅当前编辑卡使用深色边框和黄色阴影强调。
- 保存使用主按钮，取消使用次按钮，删除使用危险文字按钮。
- 删除时间轴装饰和开启徽标，减少视觉噪音。

## 状态联动

- 保存后的每条记录始终参与当前活动时间段计算。
- 开始时切换到内容对应的精神档位。
- 结束时继续使用既有规则：通常恢复“专注搬砖”，下班前 20 分钟内恢复“准备下班”。
- 清空后停止小闹钟时间段联动，但不主动改变用户当前档位。

## 测试

- 删除副标题和开启状态提示。
- 添加、编辑、取消、保存与单条删除。
- 编辑锁和操作禁用。
- 二次确认清空及取消清空。
- v2 到 v3 迁移、空列表持久化和跨日期复用。
- 保存校验、冲突、存储失败回退和升序排列。
- 现有开始、结束与下班前 20 分钟状态联动回归。

## 不在范围

- 按星期或指定日期配置不同小闹钟。
- 云端同步。
- 临时停用单条记录。
- 自动保存未完成草稿。
