# 工位小闹钟时间段与精神档位联动设计

## 目标

把“工位小闹钟”从单个时间点、独立提醒文案和独立目标状态，改为以时间段驱动精神档位的自动化工具。用户点击添加后设置开始时分、结束时分和内容；内容直接映射精神档位，开始时切入，结束时恢复。所有设置即时保存。

## 已确认的业务规则

- 每条小闹钟使用同一天内的开始时间和结束时间。
- 内容与精神档位一一对应。选择内容就是选择开始时要切换的精神档位，不再单独选择目标档位。
- 可选内容保留当前可手动选择的精神档位，但排除：
  - `working`（工作中）：已从当前精神档位中删除。
  - `focus_brick`（专注搬砖）：仅作为时间段结束后的自动恢复档位。
  - `preparing_leave`（准备下班）：仅作为下班前 20 分钟的自动档位。
- 时间段开始时切换到内容对应的精神档位。
- 时间段结束时：
  - 尚未进入下班前 20 分钟，切换到“专注搬砖”。
  - 已经进入下班前 20 分钟，切换到“准备下班”。
- 下班前 20 分钟没有活动时间段时，自动切换到“准备下班”。
- 小闹钟时间段可以进入下班前 20 分钟，并且小闹钟优先。若自动切换点到来时仍有活动时间段，则延后“准备下班”，直到该时间段结束。
- 已启用的时间段禁止重叠。未完成、未启用的草稿不参与冲突判断。
- 卡片列表按开始时间升序排列；开始时间相同时按结束时间、创建顺序稳定排序。

## 交互设计

### 新增

点击“+ 添加”后，在列表中新增并自动展开一张未启用草稿卡片：

- 开始时间默认为下一个整点。
- 结束时间默认为开始时间后 30 分钟。
- 若默认时间超出排班范围或与已有时间段冲突，草稿仍可创建，但保持未启用并显示需要调整的提示。
- 内容初始为“请选择”。
- 选择有效内容后，系统校验时间段；校验通过则自动启用并即时保存，校验失败则保持未启用并显示原因。
- 不提供单独的“保存”按钮。

### 编辑

- 开始时间和结束时间都使用独立的小时、分钟选择器，小时范围为 `00–23`，分钟范围为 `00–59`。
- 内容使用单选下拉框，选项来自可用精神档位并应用上述排除规则。
- 修改时间、内容或启用开关后立即校验并保存。
- 有效修改后重新按开始时间排序。
- 无效修改不覆盖上一次有效值，并在当前卡片内显示错误。
- 已保存卡片可以展开编辑、关闭或删除。

### 列表摘要

折叠状态使用紧凑摘要：

`10:30–11:00　会议中　已开启`

未启用草稿显示“待设置”，已关闭记录显示“已关闭”。

## 数据模型与持久化

本地存储升级为 v2。核心结构为：

```ts
type WorkdayReminder = {
  id: string;
  startTime: string;
  endTime: string;
  statusType: string | null;
  enabled: boolean;
  createdAtMs: number;
};
```

- `statusType` 同时代表用户选择的内容和开始时的目标精神档位。
- 删除旧的 `label`、`message`、`suggestedStatus` 字段。界面名称来自精神档位名称，提醒文案来自设置页中该档位启用的状态文案。
- 每次有效修改写入本地存储。写入失败时恢复上一次成功保存的状态并显示错误。
- 排序只影响展示和持久化顺序，不改变记录 ID。

### v1 数据迁移

- 旧版有效单点提醒转换为以原 `time` 开始、持续 30 分钟的时间段。
- 原 `suggestedStatus` 转为 `statusType`。
- `working` 和 `preparing_leave` 旧提醒不迁移：前者已移出可选状态，后者由新的下班前 20 分钟规则替代。
- 迁移后发生重叠或超出当前排班范围的记录保留为未启用记录，避免它们自动触发；用户可在编辑器内调整。
- 迁移成功后写入 v2 存储键，避免重复迁移。

## 调度与状态流

调度器每 15 秒计算当前时刻所处阶段，而不是只查找一个短暂的到点窗口：

1. 若当前位于一个已启用时间段内，该时间段是活动小闹钟。
2. 活动小闹钟首次进入或内容发生变化时，切换到其 `statusType`。
3. 离开活动时间段时：
   - 当前时间达到排班结束前 20 分钟，切换到 `preparing_leave`。
   - 否则切换到 `focus_brick`。
4. 当前没有活动小闹钟且已到排班结束前 20 分钟时，切换到 `preparing_leave`。
5. 已超过排班结束时间后，不再由小闹钟发起新的档位切换，交由现有下班流程处理。

因此应用在时间段开始后才打开时，只要仍处于该时间段内，就会立即进入对应档位；完全错过的时间段不会补触发。

### 活动时间段被编辑

- 修改内容：立即切换到新的内容档位。
- 关闭或删除：立即退出该时间段，并按当前时间切换到“专注搬砖”或“准备下班”。
- 修改时间导致当前时刻不再落在该时间段内：按关闭处理。
- 修改结束时间但当前仍在范围内：保持活动，按新的结束时间退出。

## 下班前 20 分钟自动化

“准备下班”不再作为普通小闹钟内容，而由排班结束时间动态计算：

- 排班结束时间变化时，自动切换点同步变化。
- 当天临时排班优先于默认排班。
- 自动切换点到达时若有活动时间段，不打断它。
- 活动时间段结束时若已经越过自动切换点，直接进入“准备下班”，不经过“专注搬砖”。

## 设置页同步

- 设置页的状态文案列表隐藏“工作中”。
- “专注搬砖”和“准备下班”继续保留，用户可编辑它们的状态文案，因为两者仍由自动化流程使用。
- 其他小闹钟可选内容对应的状态文案继续保留。
- Rust 固定状态定义保留 `working`，用于历史记录和内部兼容；前端可配置列表与选择列表统一过滤，不删除历史数据。

## 校验与冲突处理

启用一条记录前必须满足：

- `statusType` 属于允许的小闹钟内容。
- 开始时间严格早于结束时间，不支持跨日时间段。
- 时间段位于当天有效排班的开始和结束时间内。
- 与其他已启用时间段没有任何交集；首尾相接不算重叠，例如 `10:00–10:30` 和 `10:30–11:00` 合法。

错误只显示在对应卡片内。无效编辑、存储失败或状态切换失败不删除其他记录，也不破坏当前有效状态。状态切换失败沿用现有错误提示和重试机制。

## 组件边界

- `WorkScheduleEditor`：负责卡片列表、展开编辑、即时反馈和排序后的展示。
- 时间段编辑子组件：负责四个时分选择器、内容选择和开关，不承担调度逻辑。
- `workdayReminders`：负责 v2 类型、迁移、排序、时间段校验、冲突检测和当前活动时间段计算，保持为可独立测试的纯函数。
- `useWorkdayReminders`：负责持久化、草稿生命周期、活动时间段轮询和编辑后的重新计算。
- `useWorkdayStatusAutomation`：负责将活动时间段阶段转换为精神档位切换，并处理“专注搬砖”与“准备下班”的自动回落。
- 设置页状态文案组件：使用与小闹钟一致的状态过滤规则，隐藏“工作中”，保留两个自动状态。

## 测试范围

### 纯逻辑

- 下一个整点和默认 30 分钟范围。
- 开始时间、结束时间和跨日校验。
- 排班范围校验。
- 重叠、首尾相接和未启用草稿。
- 稳定升序排列。
- v1 到 v2 迁移，包括被排除状态、重叠和越界记录。
- 当前活动时间段、时间段结束回落和下班前 20 分钟优先级。

### 组件与 Hook

- 点击添加后展开未启用草稿。
- 时分选择器和内容选择即时保存。
- 选择内容后自动启用。
- 冲突修改回退并显示错误。
- 正确的摘要、排序、关闭和删除行为。
- 应用在时间段中途启动时立即切换。
- 活动时间段的内容修改、关闭、删除和时间修改。
- 小闹钟覆盖下班前 20 分钟，结束后进入“准备下班”。
- 设置页隐藏“工作中”，保留“专注搬砖”和“准备下班”。

### 回归验证

- 现有排班时间编辑、今日临时排班和下班流程继续工作。
- 精神档位手动切换继续工作，且不再显示“工作中”。
- 构建、前端测试与相关 Rust 测试通过。

## 不在本次范围

- 跨日时间段。
- 多个重叠时间段的优先级栈。
- 云端同步或 Rust 数据库存储。
- 独立的自定义提醒标题和自由文案。
- 下班后的新档位调度。
