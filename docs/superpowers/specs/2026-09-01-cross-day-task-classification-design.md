# 跨天任务分类与日期刷新设计

## 背景

Windows 桌面版当前只把“DDL 日期早于今天”的任务归入 `overdueTasks`，而 `formalTasks` 只包含计划日期或 DDL 日期恰好等于今天的任务。这个规则无法表达持续多日的任务区间，并且今日页面跨过本地零点后不会主动重新查询，导致昨日任务可能继续以旧分类显示。

## 目标

让未完成任务在计划日期至 DDL 日期之间持续显示在“今天这些破事”，并在 DDL 所在自然日结束后移动到“昨日烂尾”。没有 DDL 的任务从计划日期开始持续显示在今日待办，直到完成或取消。页面必须在本地自然日变化后自动重新分类。

## 分类规则

所有日期判断使用操作系统本地时区的自然日边界，不使用工作状态模块的 05:00 工作日边界。

对状态不是 `completed` 或 `cancelled` 的任务：

1. 计划日期晚于今天：不进入今日待办或昨日烂尾。
2. 计划日期不晚于今天，且没有 DDL：进入 `formalTasks`。
3. 计划日期不晚于今天，且 DDL 日期等于或晚于今天：进入 `formalTasks`。
4. DDL 日期早于今天：进入 `overdueTasks`，并且不再进入 `formalTasks`。

DDL 是否已经越过具体时刻不改变当天分区。任务在 DDL 当天始终留在“今天这些破事”，到次日零点重新分类后才进入“昨日烂尾”。例如计划时间为 2026-09-01、DDL 为 2026-09-30 的任务，在 2026-09-15 和 2026-09-30 都属于今日待办，在 2026-10-01 未完成时属于昨日烂尾。

既有规则保持不变：

- 当天完成的任务进入 `completedTodayTasks`。
- 已完成和已取消任务不进入正式或烂尾列表。
- `upcomingDeadlineTasks` 只包含仍处于正式列表且 DDL 具体时刻晚于当前时刻的任务。
- 正式任务继续按 DDL 优先、无 DDL 按计划时间排序；烂尾任务继续按 DDL 排序。
- 自动开始仍依据计划时刻执行，不改写任务的原始计划日期或 DDL。

## 实现边界

### 桌面端任务分类

修改 Rust 服务中的 `classify_today_tasks`，把正式列表判断从“计划日期等于今天或 DDL 日期等于今天”改为“任务已到计划日期，且尚未越过 DDL 所在自然日”。烂尾判断仍以 DDL 日期早于今天为准，并作为互斥分支，避免同一任务同时出现在两个列表。

数据库结构和已有任务数据不需要迁移。分类在查询时计算，不修改任务记录，因此历史中的计划日期和延期记录保持真实。

### 页面日期刷新

新增一个职责单一的日期刷新 Hook，由今日页面调用。它负责：

- 页面首次加载继续使用现有查询流程。
- 计算下一个本地零点并设置一次性定时器；触发查询后继续安排下一个零点。
- 窗口重新获得焦点时刷新。
- 页面从隐藏恢复为可见时刷新。
- 组件卸载时清理定时器和事件监听。

焦点和可见性事件可能连续发生，允许重复调用现有幂等查询；不增加持久化写入，也不改变任务状态。

## 平台范围

本次修复针对 Tauri 桌面应用共享代码。Windows 安装程序使用同一套 Rust 分类服务和 React 今日页面，因此无需 Windows 专属分支。独立的 `web/` 应用不属于本次 Windows 安装包修复范围。

## 测试设计

Rust 分类测试覆盖：

- 计划日当天、有未来 DDL 的任务进入正式列表。
- 计划日与 DDL 之间的任意日期仍进入正式列表。
- DDL 当天即使具体时刻已过，任务仍进入正式列表。
- DDL 次日未完成任务只进入烂尾列表。
- 跨天且无 DDL 的任务持续进入正式列表。
- 计划日期在未来的任务不提前显示。
- 完成和取消任务继续排除。
- 正式与烂尾列表不存在重复任务。

前端 Hook 测试使用模拟时间覆盖：

- 到达本地零点时触发刷新并安排下一次刷新。
- 窗口重新获得焦点时触发刷新。
- 页面恢复可见时触发刷新。
- 卸载后不再触发刷新。

完成后运行桌面前端测试、Rust 任务服务测试和生产构建。验证通过后重新生成 Windows x64 安装程序及 SHA-256 校验值。

## 验收标准

1. 计划时间为 2026-09-01、DDL 为 2026-09-30 的未完成任务，在 2026-09-15 和 2026-09-30 显示于“今天这些破事”。
2. 同一任务在 2026-10-01 只显示于“昨日烂尾”。
3. 计划日期早于今天且无 DDL 的未完成任务仍显示于“今天这些破事”。
4. 计划日期晚于今天的任务不提前显示。
5. 应用保持运行跨过零点后，无需重启即可更新任务分区。
6. 应用从后台恢复后立即按当前日期刷新任务分区。
7. 已完成、已取消任务及当天完成列表的现有行为不回退。
